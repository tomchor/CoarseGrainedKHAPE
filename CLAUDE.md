# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

KHAPE (Kelvin-Helmholtz Available Potential Energy) computes Available Potential Energy (APE) from Kelvin-Helmholtz instability simulations using the Winters et al. (1995) sorting method. The pipeline is:
1. **Julia simulation** (Oceananigans.jl on GPU) -> NetCDF output, including every term of the sub-filter KE and APE budgets at the online filter scales
2. **Python post-processing** -> assemble and plot the budgets from those online terms; the offline recomputation of the same terms is kept only as a CI cross-check; the sweep over filter scales stays offline

GitHub remote: `git@github.com:tomchor/CoarseGrainedKHAPE.git`

## Running the Code

### Full pipeline (simulation + post-processing + sweep)
```bash
bash submit_all_pbs.sh                        # default Nz=2048
bash submit_all_pbs.sh NZ=1024 FIXED_REF=1   # custom resolution; FIXED_REF applies to the sweep transfer only
```
Jobs are chained via PBS `afterok` dependencies. Always use `submit_*.sh` wrappers, never submit `*.pbs` files directly.

### Simulation only
```bash
bash submit_simulation.sh NZ=2048
```
Account: `$KHAPE_ACCOUNT`, which every submit wrapper passes with `qsub -A` (and `$KHAPE_PYTHON` for the Python jobs; see README, Environment); queue: `casper`, 1x A100, 8 cores, 64 GB RAM.

The Julia simulation accepts CLI args: `--Nz`, `--Ri`, `--stop_time`, `--Re0`, `--Pr`, `--U`, `--h`, `--perturbation_amplitude`, `--filter_ls` (one or more online filter length scales ℓ; default `1 7`; every term of both SFS budgets is written at each), `--save_tensors` (flag; also writes the per-scale strain/stress tensor components for online-vs-offline validation), and `--save_sorted` (flag; also writes the validation-only view of the Winters (1995) sorted reference state: the two model-grid z✶ methods, the sorted column, ∫E_b). For local CPU development:
```bash
julia --project -t 8 kelvin_helmholtz_instability.jl
julia --project -t 8 kelvin_helmholtz_instability.jl --Nz 512 --Ri 0.1 --stop_time 70 --Re0 1e-3
```

### Post-processing only
```bash
cd postprocessing
bash submit_budgeting.sh NZ=2048       # assembles the budgets from the online terms and plots them; minutes
bash submit_sweep.sh NZ=2048 FIXED_REF=both
```

### Local post-processing (no PBS)
```bash
cd postprocessing
bash 00_get_budgets.sh output/khi_Nz512_Ri0.10.nc --filter-scales 1 7        # 01_online_budgets.py + 02_plot_budgets.py
N_WORKERS=4 bash offline/run_offline_budgets.sh output/khi_Nz512_Ri0.10.nc --filter-scales 1 7   # the offline pipeline, into output/offline/
```
`--filter-scales` must be among the simulation's `--filter_ls` (default: every scale it wrote). The offline pipeline is not a product: it exists for `pytest --offline-check` (below). `N_WORKERS` (default 1) is its parallelism.

### Running tests
```bash
pytest tests/ -v -s                                  # closure, positivity, synthetic filter and Jensen tests (minutes)
pytest tests/ -v -s --offline-check                  # + the offline pipeline as a cross-check (about an hour at Nz=1024, less at CI's Nz=512)
pytest tests/test_gaussian_filter.py -v -s           # single file (filter unit tests, no pipeline output needed)
pytest "tests/test_budgets.py::test_ke_budget_residual" -v -s   # single test
```
`test_budgets.py` checks SFS KE and APE budget closure (rms(residual)/mean(rms(terms)) < 1%; the mean rather than the smallest term, so that no single small term sets the metric) and **requires the assembled budget files** in `postprocessing/output/` for `khi_Nz512_Ri0.10`, the CI run (run `00_get_budgets.sh` first; it is parametrized per filter scale via `conftest.py`). That name is set once, as `STEM` in `tests/conftest.py` (`$KHAPE_TEST_STEM` overrides it), with `SIM_OUTPUT` derived from it. `test_filter.py` / `test_gaussian_filter.py` are self-contained unit tests of the offline `GaussianFilter` and need no pipeline output.

`test_positivity.py` checks the energies whose sign is fixed by construction: the local APE Eₐ (of the full field, of the filtered field, and filtered) and the SFS KE ½τᵢᵢ, each held to `min(field) > -tol x rms(field)`. The tolerance is 1e-3 for the APE, whose nearest-slot z✶ lookup leaves a fraction of the domain a hair below zero, and 1e-8 for the SFS KE, which is non-negative by Jensen and so may only lose roundoff (the online Kˢ measured strictly positive at Nz=1024). It reads the `*_budget_fields*.nc` files the assembler writes, plus the online `E_a` from the simulation output. It also checks the SFS APE S̃ (`test_sfs_ape_is_positive`). `test_jensen.py` explains why S̃ has a sign: on a synthetic wave-displaced stratification it checks that the remainder Eₐˢ **is** non-negative pointwise when the filter acts in x alone (eₐ(·, z) is convex in b, so Jensen applies when every kernel weight sits at one height) and that it goes negative once the filter also acts in z, which is what `filtered_dimensions` does. Those synthetic tests need no simulation or post-processing output; they are the justification for the filtered-reference construction, so they stay. The file's last test applies the bound to the simulation's own `E_as_ℓ<ℓ>`, which is S̃ and so is asserted non-negative — to 3e-3 of rms, as `test_positivity`, since online S̃ carries the nearest-slot z✶ lookup on both profiles; the dip shrinks with the model resolution (−1.14e-3 at CI's Nz=512, −4.8e-5 at Nz=1024), not with the profile's. Note that S̃ dips below zero during the small-amplitude phase (t ≲ 6 at ℓ=1, at the 1e-7 level against a developed rms of 1e-3) in both pipelines identically; the whole-run rms hides it, and `test_offline_check.py` asserts the two pipelines agree on it record by record.

**`--offline-check`** (`tests/conftest.py`, off by default) runs `postprocessing/offline/run_offline_budgets.sh` unless its output exists in `postprocessing/output/offline/`, then `tests/test_offline_check.py` compares every field and integral of the offline budgets against the assembled online ones, term by term, at tolerances set from measurement (about 3× the values measured on the Nz=1024 run of 2026-09-26: S̃ 1e-5, Rˢ 2e-4, τ 1e-3, ε_Aˢ 6e-3, Π_A 2e-2 in rms), plus the offline budget's own closure (the same metric at 3%: the offline ε_Aˢ takes centred gradients where the online one pairs its factors on faces, which alone puts the offline residual at 2.3% of the mean term at Nz=512 and 1.2% at Nz=1024, against 0.85% and 0.48% online; with the online ε_Aˢ substituted the two residuals agree to 1e-5, so the offline closure can never be held tighter than the online one) and the agreement of the per-record minima of S̃; `tests/test_online_vs_offline.py` (the `inv0*` validation scripts, which recompute their quantity offline) runs under the same gate. The offline pipeline is the independent implementation: scipy filtering on a z-padded domain, a numpy sort, an FFT-filtered reference profile, centred gradients. `offline/04_sfs_ke_budget.py --recompute-online-terms` makes it recompute Π_K and ε_Kˢ too, so no row of the check compares an online field with itself.

## Architecture

### Post-processing pipeline (`postprocessing/`)

The budgets are computed by the simulation; the Python side assembles and plots them. `00_get_budgets.sh` runs the two scripts in sequence:

| Script | Purpose |
|--------|---------|
| `01_online_budgets.py` | Read every online SFS KE and APE term (fields and `_int` integrals) at the upper record of each output pair and write `<stem>_sfs_{ke,ape}_budget_{fields,integrated}.nc` under the variable names the offline pipeline used to write, on the simulation's own grid (`n_pad_z = 0`) |
| `02_plot_budgets.py` | Plot the integrated budgets, one figure per filter scale |

`offline/` holds the offline pipeline, which is **not a product** but the independent implementation the CI check runs (`offline/run_offline_budgets.sh`, output in `output/offline/`; see *Running tests*): `01_filter_fields.py` (Gaussian-filter velocity and buoyancy on a z-padded domain), `02_sort_density.py` (Winters sort of the padded field), `03_energy_transfer.py` (Π_A and the APE↔KE exchange), `04_sfs_ke_budget.py` (SFS KE budget; `--recompute-online-terms` recomputes Π_K and ε_Kˢ too), `05_sfs_ape_budget.py` (SFS APE budget: local APE, S̃, ε_Aˢ, Rˢ, tendency). The variant flags they used to carry (`--fixed-reference`, `--reference true`) are gone with the offline product; the sweep keeps `--fixed-reference`.

`sweep*` scripts are the sweep variant (parameter sweep over filter scales; `submit_sweep.sh EXTENSION=odd` runs it with b oddly reflected past the walls into `_odd` files, and a run over a subset of scales, e.g. the wall-extension test `submit_extension_test.sh` submits, tags its files `_l<scales>` so it never replaces the full sweep; `sweep2` writes only the `∫` integrals, which is all its readers use, unless given `--keep-fields`): `sweep1_filter_fields.py` filters, `sweep2_energy_transfer.py` computes transfer, `sweep3_plot_transfer_spectrum.py` plots spectra. The sweep stays offline: at its widest scales the matched filter's stencil exceeds one period in x and CUDA's kernel-parameter space in z, and its odd wall extension has no online counterpart.

`postprocessing/validation/` holds the online-vs-offline comparison scripts, each of which recomputes a quantity offline and compares it against the simulation's online output: `inv01_compare_filters.py` (filtered fields), `inv02_compare_ke_transfer.py` (Π_K), `inv03_compare_tensor.py` (the S̄/τ tensor components), `inv05_compare_dissipation.py` (SFS KE dissipation ε_Kˢ), `inv06_compare_sorted_profiles.py` (the Winters sorted reference state: the sorted profile b✶(z✶) and the reference height z✶, for all three sorting methods), `inv07_compare_local_ape.py` (the local available potential energy Eₐ, field and integral), `inv08_compare_sfs_ape_dissipation.py` (the sub-filter APE dissipation ε_Aˢ at every filter scale, field and integral), and `inv09_compare_ape_transfer.py` (the cross-scale APE flux Π_A). `inv10_online_budget_closure.py` checks that the online budgets close from the `_int` series alone (`--offline-stem` sets the offline pipeline's residual beside it). `inv04_animate_comparison.py` makes the animated online | offline | difference version for a chosen `--field` (Π_K, ε_Ks, or a filtered field). `validation.pbs` runs them all. Each writes exactly **one** figure, to `figures/validation/` (their own subdirectory, so they stay separable from the budget and paper figures in `figures/`); CI uploads that directory as the `validation-plots` artifact. The tensor-component comparison (`inv03`) needs a `--save_tensors` run and the sorted-state comparison (`inv06`) a `--save_sorted` run; every budget term is always written.

Standalone visualization scripts (not part of the numbered pipeline):
- `plot1_panels.py` -- 4-panel snapshot of local SFS budget fields
- `plot2_budgets.py` -- 2x2 panel of SFS KE and APE budget time series
- `plot3_plot_transfer_spectrum.py` -- cross-scale transfer spectra
- `anim1_panels.py` -- animated version of plot1 panels (requires ffmpeg); reads the assembled budget files and the online `b_r` from the `_2d.nc` file

Shared utilities:
- `aux00_utils.py` -- data loading (`load_dataset_and_grid`, `pad=False` for the simulation's own grid), filtering (`filter_fields`, `GaussianFilter`, `DaskParallelFilter`), domain padding (`_pad_domain_in_z`), spatial derivatives (`calculate_gradient`), tensor condensing (`condense_velocities`)
- `aux01_pe_functions.py` -- density sorting (`sorted_timeseries`), potential energy calculations (`local_potential_energies_timeseries`), APE budget terms (SFS flux tensor, cross-scale APE flux, total APE dissipation `calculate_ape_dissipation`, SFS APE dissipation, reference-tendency correction R), the FFT-filtered reference profile (`filtered_reference_profile`)
- `aux02_ke_functions.py` -- SFS stress tensor, strain rate tensor, cross-scale KE flux, SFS KE dissipation, full energy transfer pipeline (`calculate_energy_transfer`, with an `include_pi_k` flag to skip Π_K)
- `aux03_plotting.py` -- plotting helpers (`budget_colors`, `run_label`, `plot_sfs_budget`)

The budget scripts accept `--filename` and `--filter-scales`; the offline and sweep scripts also `--n-workers`, and the sweep `--fixed-reference`. Output goes to `postprocessing/output/` (`$KHAPE_PP_OUTPUT`), the offline pipeline's to its `offline/` subdirectory.

### Data flow between pipeline steps

**Production.** Every term of both SFS budgets is written by the simulation at each online filter scale (`--filter_ls`, default `(1, 7)`): the fields `K_s_ℓ<ℓ>`, `dKs_dt_ℓ<ℓ>`, `Π_K_ℓ<ℓ>`, `ε_Ks_ℓ<ℓ>`, `wb_rs_ℓ<ℓ>`, `E_as_ℓ<ℓ>`, `dEas_dt_ℓ<ℓ>`, `Π_A_ℓ<ℓ>`, `ε_As_ℓ<ℓ>`, `R_s_ℓ<ℓ>`, the two halves of S̃ (`L_ℓ<ℓ>`, `Ea_flt_ℓ<ℓ>`, 3D writer only), the scale-independent `E_a`, and a `_int` volume integral of each term. `01_online_budgets.py` reads them (`load_dataset_and_grid(pad=False)`, upper record of each `ConsecutiveIterations` pair, where the online `TimeDerivative` is the same single-step difference the offline pipeline formed) and writes the four budget files, with `ape_reference="filtered"`, `budget_source="online"` and `n_pad_z=0` in their attributes; `02`, `plot3`/`plot4`, `anim1`, `S2`/`S4` and the tests read those files and never the simulation's budget terms directly. `anim1` and `S5` take `b_r` from the `_2d.nc` file. The budget filter scales must be among the simulation's online `filter_ℓs`; `01` raises otherwise, and `--filter-scales` defaults to every scale it wrote.

**The offline check** (`offline/`, `pytest --offline-check`) keeps the old data flow among its own steps, in `output/offline/`: `01` pads the domain to 4σ of the widest scale and records the margin, `02` sorts the padded field, and `03`–`05` read the margin back and refuse a sorted file whose `n_pad_z` or `z_extension` differs from the grid they loaded (`check_same_padded_grid`); `05` reuses its per-scale checkpoints only when stamped with the same run (a hash of the dataset's attributes and time axis); `04 --recompute-online-terms` recomputes Π_K and ε_Kˢ rather than reading them, so the check is independent term by term; `05` reads `04`'s exchange term and `03`'s Π_A. `tests/test_offline_check.py` then compares each variable of the offline files against the assembled ones.

**The sweep** (`sweep1`–`sweep3`) is offline and self-contained: it pads to 4σ of ℓ=20, sorts its own column (`sweep2 --fixed-reference` freezes t=0 by sorting it once and broadcasting), and reads nothing from the budget pipeline.

### Filtered-reference scale decomposition

> **Why it is this way:** `filtered_reference_decisions.md` is the decision record for this work — what was
> tried, what was measured, and what was rejected. Read it before changing how ⟨ρ_*⟩ is built, how the
> sub-filter flux and dissipation are computed, or how the integrals treat the z padding. Several of those
> choices look arbitrary and are not, and one of them (the coarse column parameterised by levels-per-σ) was
> a wrong turn that cost real time to diagnose and undo.

The resolved reservoir is measured against the vertically filtered reference profile ⟨ρ_*⟩ (⟨b✶⟩ online), and only against it: the `--reference true` comparison path was dropped with the offline product.

The pipeline filters in x **and** z (`filtered_dimensions = ["x_caa", "z_aac"]`). For a kernel with vertical extent the two reservoirs cannot both be measured against the unfiltered ρ_*: a fluid at rest filters to a profile that still carries APE against ρ_*, so the resolved reservoir does not vanish at rest and the remainder Eₐˢ = filter(eₐ) − eₐ(ρ̄) goes negative. That is the whole content of `test_jensen.py`.

Wenegrat, Chor & Barkan resolve it by measuring the resolved reservoir against the rest state *as the filter sees it* — the vertically filtered profile ⟨ρ_*⟩ (their Eq. 2.3): `L̃ = Ẽ_A(ρ̄, z)` against ⟨ρ_*⟩, `S̃ = Ē_A − L̃`, `Υ̃ = z̃_*(ρ̄) − z`, and `b̄_r = b̄ − ⟨b_*⟩(z)` — which against ⟨ρ_*⟩ is exactly filter(b_r), since ρ_*(z) depends on z alone. Both reservoirs are non-negative and both vanish at rest, for any kernel, up to the lookup granularity: during the small-amplitude phase (t ≲ 6 at ℓ=1) S̃ is a ~7% residual of two ~4e-6 quantities and dips to −0.7 of that record's rms (|values| ~2e-7 against a developed rms of 2e-3), identically in both pipelines. Measuring both reservoirs against the unfiltered ρ_* is the `g_z = δ(z)` horizontal-filter limit (their Eq. 2.24–2.26), correct only for a horizontal kernel, and is what both pipelines did before PR #68: the negative SFS APE seen in the animations before then was that remainder.

Online, ⟨b✶⟩ is the `VerticalSort` column block-averaged onto a coarse column of K=1000 levels per σ, filtered there with the vertical marginal of the same Gaussian (a repo-local kernel with device-array weights: Oceanostics' `NTuple` kernel overflows CUDA's parameter space at that width), and linearly interpolated back onto the N slots for the lookup. Offline (`filtered_reference_profile`, the check) it is an exact FFT convolution of the whole column. Measured at Nz=1024 the two differ by ≤1e-5 on S̃ and 0.007% on ∫Π_A (`filtered_reference_decisions.md` §3, §9), below every tolerance of the offline check, so the coarse column stays; porting the FFT online (a custom `compute!` with CUFFT, as `ReferenceTendencyCorrection`) remains possible and nothing now depends on it.

Three consequences worth knowing:

- **The online APE terms are the filtered-reference ones, and they are the budget.** `Π_A_ℓ<ℓ>` / `ε_As_ℓ<ℓ>` / `E_as_ℓ<ℓ>` / `R_s_ℓ<ℓ>` are built against ⟨b✶⟩; no unfiltered counterpart is written. The offline check recomputes them against the exact FFT ⟨ρ_*⟩ with centred gradients: the online ε_Aˢ is the better discretised of the two (it pairs its factors on the faces where both differences live), and at Nz=1024 the two agree to 0.4–0.6% in rms, 0.5% on the integral over the run.
- **`⟨ρ_*⟩` is scale-dependent**, so it is rebuilt inside each filter-scale loop rather than once per run.
- **Cost is essentially unchanged.** The construction is the same lookup and the same cumulative integral against a different profile; the only new work is one 1D convolution of the profile per timestep. The expensive full-field sort in `offline/02` is untouched and still shared. A *frozen* profile is filtered once and broadcast rather than once per output (callers pass `frozen=`, checked against the first and last rows, rather than the function comparing every row), since `sorted_timeseries(fixed_reference=True)` repeats one row — bit-identical, and 12–45× faster at Nz=128.

- **The offline z padding is sized to the widest filter.** `S̃ = Ē_A − L̃` is an identity only where `filter(z) = z`, which fails within one stencil of an array boundary. `required_pad_margin` asks for 4σ of margin; `offline/01`/`sweep1` pad with it and record it on the filtered-fields file, and `offline/02`–`05`/`sweep2` read it back so every step sees the same padded grid. The simulation has no padding: its filter extends the bounded z axis with the wall value, and the walls sit deep in the saturated tanh where E_A ≈ 0, which is why the online S̃ matches the padded offline one to 1e-5. The old fixed `Nz//2` gives a margin of Lz/2 = 12.5, which is just enough for ℓ = 7 (4σ = 11.89) and fails from ℓ ≈ 7.7 — the next scale in the sweep's `geomspace(0.02, 20, 30)`, whose top end needs 33.97. A run at ℓ ≤ 7 is unchanged, bit-identical. **This fixes only the stencil-truncation half of the large-ℓ problem:** a filter whose σ is a third of the domain also flattens ⟨b_*⟩ until its inverse z̃_* is poorly conditioned, and padding cannot fix that. The profile filter itself is an FFT convolution of the column, O(N log N) in its length, so wider padding costs little there.

`test_filtered_reference.py` pins this down on the synthetic field of `test_jensen.py`: S̃ and L̃ are non-negative, both vanish for a fluid at rest while L measured against the unfiltered ρ_* does not, and the remainder construction still breaks on the same field. (L̃ + S̃ = Ē_A is not tested: S̃ is defined that way.) Measured interior min/rms for S̃ is +8.6e-06, +6.9e-05 and +2.0e-03 at ℓ = 2, 4 and 8 cells, against −0.69, −2.31 and −2.67 for the remainder, which is negative over 15–48% of the domain.

**Edge caveat.** S̃ is computed as Ē_A − L̃, an identity that needs filter(z) = z. `GaussianFilter` extends the bounded z axis with its edge value, so within a stencil of a wall the kernel is one-sided and the identity picks up a spurious τ(z, b). On `test_jensen.py`'s shorter column, whose stratification reaches the walls, every violation lives in that band and nowhere else, which `test_filtered_reference.py::test_edge_cells_are_the_only_place_the_identity_fails` asserts; it also fails if that column stops violating at all, or if `EDGE_BAND_SIGMAS` grows past the kernel's 4σ reach. The production pipeline does not meet this, because `_pad_domain_in_z` pads the domain with edge values at load time, by at least Nz//2 cells each side and at least 4σ of the widest filter, putting the physical domain far from the filter's edge.

**The online APE set.** The simulation writes the filtered-reference set per scale unconditionally — `E_as_ℓ<ℓ>` (S̃) with its two halves `Ea_flt_ℓ<ℓ>` (Ē_A) and `L_ℓ<ℓ>` (L̃, 3D writer only), `Π_A_ℓ<ℓ>`, `ε_As_ℓ<ℓ>`, `R_s_ℓ<ℓ>` and the S̃ tendency `dEas_dt_ℓ<ℓ>` — under the plain names, the unfiltered set having been removed entirely so that nothing downstream can read the superseded formulation by accident. Υ̃ is built inside the terms and not written. (`wb_rs_ℓ<ℓ>`, the APE→KE conversion, is filter(w(b − b✶)) − w̄(b̄ − ⟨b✶⟩): its resolved half is on ⟨b✶⟩ like every other term, matching `04`. Upstream's `SubFilterAvailablePotentialToKineticEnergyConversion` reads one profile for both halves, so neither `method=lookup` nor `method=lookup_flt` gives this split; the simulation adds the filtered conversion against b✶ and subtracts it against ⟨b✶⟩, which moves the pointwise field and leaves every integral as it was, since ∫w̄ f(z) dV = 0. It is a reversible exchange, so **neither half of the filtered/sub-filter separation is sign-definite** and no positivity test applies to it — unlike ε_Kˢ or S̃. It is also load-bearing: `inv10` reads `wb_rs_ℓ<ℓ>_int` in *both* budgets, where at Nz=128/Re=262 it is the largest KE term at ℓ=1, and `plot_kelvin_helmholtz_instability.jl` discovers its panel scales from the `wb_rs_ℓ*` names, so removing it deletes every panels animation. `01_online_budgets.py` reads it into both budget files; the offline check builds its own exchange in `04` and compares.) It needed no Oceanostics change: `ProfileLookup` accepts an external profile as a pair of `Field`s and refreshes it on every `compute!` (`refresh_profile_source!(p::Field, time) = compute_at!(p, time)`), supplying one skips the O(N log N) sort, and the two-argument constructors `AvailablePotentialEnergy(model, z✶)` / `FilteredAvailablePotentialEnergy(model, z✶ˡ)` / `AvailablePotentialEnergyCrossScaleFlux(model, filter, z✶ˡ)` let the two halves carry different profiles, composed in the simulation script exactly as `R_s = Field(gf(R_full)) - R_l` already is. Three things that cost real time to learn and are easy to undo by accident:

- **Composed expressions must be wrapped in a `KernelFunctionOperation`** with a trivial passthrough kernel, as every Oceanostics diagnostic already does (`subfilter_ape_ccc` and friends). A writer specialises on the type of its whole output NamedTuple, and an unwrapped `Field(gf(Field(a))) - b` is a deep `BinaryOperation` nest; several of those sent LLVM's instruction selector quadratic (`DAGCombiner::CombineToPostIndexedLoadStore` → `hasPredecessorHelper`) and stalled compilation of the writer for **>45 min at Nz=32**. `flatten` in the simulation script collapses each term to one flat type. Symptom: the run sits at 100% CPU writing nothing, because Julia buffers stdout and stderr when redirected — an explicit `flush` is the only way to see where it is.
- **Keep the 2D panels writer's tuple small and keep the `flatten` wrappers on it.** It carries the per-scale set so `plot_kelvin_helmholtz_instability.jl` draws the panels animation from the filtered-reference fields, which is the whole point, but it is the largest output tuple and therefore where the LLVM stall above bites first.
- **Measured at Nz=128/Re=262**, the online construction beats the offline one on every count: at rest L̃ is 1.09e-07 (ℓ=1) and 8.04e-08 (ℓ=7) against 1.56e-07 and 1.13e-07 offline, with the true-reference `E_a` at machine zero; S̃ min/rms is −9.4e-03 and −1.2e-06 against −2.7e-02 and −1.6e-06, and at ℓ=7 the interior is strictly positive. The online path has no z padding, so the filter's edge band sits in real fluid — measured, that costs nothing here (edge band machine-clean at ℓ=1, worst violation in the interior), because the domain's z walls sit deep in the saturated tanh where b is uniform and E_A ≈ 0.

**Open question:** which grid ⟨b_*⟩ is built on. Offline it is the sorted column, whose slots are uniform only because the model grid is; Oceanostics' filter is grid-general, so building ⟨b_*⟩ on the column with a single rescaled σ would narrow that. The alternative — filter `ReferenceProfileAtHeight` on the model grid, then interpolate onto the column heights for the lookup — keeps both the grid-generality and the height resolution, and needs testing. Note also that Oceanostics' own docstring (`FilteredAvailablePotentialEnergyEquation.jl`, on `FilteredAvailablePotentialEnergy`) still asserts the filtered buoyancy must be measured against the same profile as the full one, which is the assumption this construction overturns.

### Julia layer
- `kelvin_helmholtz_instability.jl` -- main simulation (Oceananigans.jl `NonhydrostaticModel`, `Centered(order=4)` advection, adaptive timestep via `TimeStepWizard`)
- `utils.jl` -- `closest_factor_number()` (FFT-friendly grid sizes), `show_gpu_status()`
- `filtered_reference_profile.jl` -- ⟨b✶⟩: the sorted column block-averaged onto a coarse column of `REFERENCE_FILTER_K` levels per σ, filtered there with the vertical marginal of the Gaussian (device-array weights, since Oceanostics' `NTuple` kernel overflows CUDA's parameter space at that width), and interpolated back onto the column's slots
- `online_diagnostics.jl` -- the only budget term Oceanostics does not provide: `ReferenceTendencyCorrection` (R = ∫_{z✶}^{z} ∂ₜb✶ dz̃). The sub-filter APE→KE conversion τ(w, b_r) used to live here too; it moved upstream in Oceanostics PR #301 as `SubFilterAvailablePotentialToKineticEnergyConversion`, which builds both halves of the split from one kernel and one `b✶(z)` rather than differencing two separately-built diagnostics
- Setup: shear flow u(z)=U·tanh(z/h), stratification b(z)=B₀·tanh(z/h) with B₀=U²·Ri/h; perturbation seeded on w. Defaults U=1, Ri=0.1, h=1
- Domain: Lx=λ_max (the most-unstable KH wavelength ≈14.1h), Ly=λ_max/3, Lz=25h; topology (Periodic, Periodic, Bounded). `y_aspect_ratio=Inf` ⇒ **Ny=1**, so runs are effectively 2D in x–z (v ≡ 0)
- Output: `output/khi_Nz<Nz>_Ri<Ri>.nc` (3D fields, Float64, consecutive-iteration pairs for time derivatives) and `output/khi_Nz<Nz>_Ri<Ri>_2d.nc` (x–z slice, Float32)

#### Online cross-scale diagnostics
The simulation computes, at each scale in `filter_ℓs` (set by `--filter_ls`, default `(1, 7)`), the sub-filter quantities the offline pipeline would otherwise recompute in Python — so they are produced once, on the GPU, and read back later (see Data flow):
- Filtered fields (Oceanostics `GaussianFilter`), the cross-scale KE flux Πₖ = −τⁱʲ S̄ⁱʲ (`KineticEnergyCrossScaleFlux`), and the SFS KE dissipation ε_Kˢ = filter(ε) − ε̄ (where `ε` is the total viscous dissipation `KineticEnergyEquation.DissipationRate` and `ε̄` is `CoarseGrainedKineticEnergyDissipationRate`, the filtered-flow dissipation). For validation only, the resolved strain rate S̄ⁱʲ (`StrainRateTensor`) and sub-filter stress τⁱʲ = filter(uⁱuʲ) − ūⁱūʲ (`subfilter_stress_tensor`) components are also emitted.
- The Gaussian filter is configured to **match the offline filter exactly**: periodic x, edge-extended bounded z, stencil truncated at 4σ (matching scipy `gaussian_filter1d`'s default `truncate=4`; Oceanostics defaults to 2σ). Only i,j ∈ {1,3} are kept (2D x–z).
- `Π_K_ℓ<ℓ>` and `ε_Ks_ℓ<ℓ>` (and their volume integrals) are always written and read by `01_online_budgets.py`, as are `K_s_ℓ<ℓ>` and `dKs_dt_ℓ<ℓ>`; the individual S̄/τ components (`S11/S33/S13_ℓ<ℓ>`, `tau11/tau33/tau13_ℓ<ℓ>`) are gated behind `--save_tensors` and consumed only by `postprocessing/validation/`. The written filtered fields `u_ℓ<ℓ>`/`w_ℓ<ℓ>`/`b_ℓ<ℓ>` use the same `matched_filter` as every term (they once used Oceanostics' 2σ/`:shrink` defaults).
- The online diagnostics come from the Oceanostics 0.21.2 release, and `TimeDerivative` from the Oceananigans 0.113.3 release; the Manifest is resolved with Julia 1.13 and tracks no branch of either. The filtered-reference APE terms are composed in the simulation script from those diagnostics, a filtered full-field term against b✶ minus a filtered-state term against ⟨b✶⟩, and the repository has its own code where Oceanostics has none: `ReferenceTendencyCorrection` in `online_diagnostics.jl`, the coarse-column construction of ⟨b✶⟩ in `filtered_reference_profile.jl` (`filtered_reference_profile`, built from `coarse_column`, `coarse_filter` and `_interp_from_coarse_ccc`), and `flatten`. Oceanostics provides `GaussianFilter`, `StrainRateTensor`, `subfilter_stress_tensor`, `KineticEnergyCrossScaleFlux`, `SubFilterKineticEnergyDissipationRate`, the whole `BackgroundPotentialEnergyEquation`/`AvailablePotentialEnergyEquation` reference-state machinery, `AvailablePotentialEnergyCrossScaleFlux` (PR #295), `SubFilterAvailablePotentialToKineticEnergyConversion` (PR #301), the `FilteredAvailablePotentialEnergyEquation` family, and `AvailablePotentialEnergyDisplacementPotential`/`AvailablePotentialEnergyDissipationRate` (0.20.0 renamed the first from `BuoyancyDisplacementPotential`). Note 0.19.0 renamed `KineticEnergyBuoyancyProduction` → `PotentialToKineticEnergyConversion`; this repo does not use it.

#### Online sorted reference state
Oceanostics' `AvailablePotentialEnergyEquation` module sorts the buoyancy field adiabatically into its minimum-PE state, giving the Winters et al. (1995) reference height z✶. The simulation always builds the sorted column with `VerticalSort` (`z✶_1dsort`, `b✶_1dsort`, on its own N = Nx·Ny·Nz vertical axis) and every APE term reads it through one `ProfileLookup`, so all scales share one sort per output. `--save_sorted` writes the validation-only view of the same state for `inv06`/`inv07`: the column itself, ∫E_b, and z✶ under the two model-grid methods, which describe the same reference state but differ in where they place cells of *equal* buoyancy:
- `z✶_3dsort` (`ThreeDimensionalSort`) and `z✶_heaviside` (`HeavisideIntegral`) — 3D fields on the model grid. Tied cells take consecutive slots in the first and share their layer's mid-height (Winters eq. 11) in the second; the `ProfileLookup` the budget uses puts a tie run at the mid-height of the band it fills, as `HeavisideIntegral` does.
- All of these go in the **main** output file: one `NetCDFWriter` holds both grids (as the upstream `lock_release.jl` example does). The cost is that a writer holding two grids makes Oceananigans suffix every dimension (`x_caa` → `x_caa_grid1` for the model grid, `_grid2` for the column) and rename the metadata groups (`underlying_grid_reconstruction_kwargs` → `grid_1_...`). The Python side reads the plain names, so `load_dataset_and_grid` strips the model grid's suffix at load time (`model_grid_suffix` / `strip_grid_suffix` / `open_grid_group` in `aux00_utils.py`); the column keeps its own suffix and is read by `inv06`/`inv07`. The 2D slice writer gets the model-grid `outputs` plus the per-scale budget terms and `b_r` (all model-grid), so it stays single-grid; those slices are what let `plot_kelvin_helmholtz_instability.jl` draw the SFS-budget panels animation (`animations/khi_Nz<Nz>_Ri<Ri>_panels_l<ℓ>.mp4`, the online counterpart of `anim1_panels.py`) straight from the `_2d.nc` file.
- Only the column is a reference *profile* as written. For the two model-grid methods `reference_buoyancy` is the model's own `b` (already an output), so their profiles come from ordering the (z✶, b) pairs by z✶ — see `profile_from_model_grid` in `inv06`, and the `lock_release.jl` example upstream.
- `b✶` (from `reference_buoyancy`) recomputes itself: its `compute!` delegates to the parent `z✶`, so handing it to an output writer triggers the sort, and the status gate means listing both does not sort twice. Earlier revisions of the branch returned a bare `Field` that `compute!` ignored, which silently wrote the *previous* output's profile; fixed upstream via `SortedBuoyancyState`. `inv06` asserts `b✶` is a permutation of `b`, which guards against a regression.
- The **online local available potential energy** `E_a` (the local field, `AvailablePotentialEnergy(model, z✶_lookup)`) and its integral `∫E_a` are always written. `AvailablePotentialEnergy` computes the Holliday & McIntyre (1981) integral density Eₐ = ∫_{z✶}^{z}[b✶(z̃) − b] dz̃, identical to the offline `ape` field in `local_potential_energies_timeseries` (with b = g(ρ₀−ρ)/ρ₀); `inv07_compare_local_ape.py` checks the two, and `01_online_budgets.py` writes it as `Ea(ρ, z)`.
- The API was renamed upstream: `sorted_reference_height` → `reference_height`, `sorted_buoyancy` → `reference_buoyancy`, `OneDimensionalSort` → `VerticalSort`, `AbstractSortingMethod` → `AbstractReferenceHeightMethod`.
- The offline check sorts the *z-padded* domain (`load_dataset_and_grid` pads it with edge values at load time) while the online sort sees only the true domain, so the two do not sort the same field; `inv06_compare_sorted_profiles.py` quantifies that, running the offline sort both padded and unpadded to separate the padding effect from any genuine online-vs-offline difference.

#### Online sub-filter APE dissipation ε_Aˢ
Per online filter scale, the simulation builds the diffusive sink of the sub-filter APE budget from Oceanostics' `AvailablePotentialEnergyDissipationRate`, measured against b✶ and then filtered, and `FilteredAvailablePotentialEnergyDissipationRate`, measured against ⟨b✶⟩. The single-profile `SubFilterAvailablePotentialEnergyDissipationRate` (Oceanostics PR #293) is not used, since it measures both halves against one profile:
- **ε_Aˢ = filter(ε_A) − ε̃ˡ**, with **ε_A = κ ∂ᵢb ∂ᵢΥ** the total APE dissipation, **Υ = z✶ − z** the buoyancy displacement potential, **ε̃ˡ = −q̄ᵢ ∂ᵢΥ̃** with **q̄ᵢ = filter(qᵢ)** the filtered diffusive flux, **qᵢ = −κ ∂ᵢb** (so ε̃ˡ = +filter(κ ∂ᵢb) ∂ᵢΥ̃), and **Υ̃ = z̃✶(b̄) − z**, the filtered buoyancy's reference height looked up in ⟨b✶⟩. Output as `ε_As_ℓ<ℓ>` and `ε_As_ℓ<ℓ>_int`, matching the `Π_K_ℓ<ℓ>` / `ε_Ks_ℓ<ℓ>` naming; `01_online_budgets.py` writes it as `ε_Aˢ`. The offline check recomputes it with `calculate_sfs_ape_dissipation`, and `inv08` compares the two.
- **Only ε_Aˢ is written.** Υ and the total ε_A are Oceanostics' `BuoyancyDisplacementPotential` and `AvailablePotentialEnergyDissipationRate` (both developed here and merged upstream in PR #276); the script builds ε_A and Υ̃ only to form ε_Aˢ; neither is a budget term, so neither is written.
- **What ε_A is.** It is the sink of the local APE equation (the paper's Eqs. 11 and 14, where it enters as −ε_A). With `∂Eₐ/∂b = z✶ − z = Υ`, the diffusive part of `DEₐ/Dt` is `Υκ∇²b = ∇·(κΥ∇b) − κ∇Υ·∇b`. Written out, `ε_A = κ[(∂z✶/∂b)|∇b|² − ∂b/∂z]`: the Winters diapycnal mixing rate less the diffusion the reference state undergoes on its own. The two cancel exactly for a statically stable, horizontally uniform stratification (z✶ = z), so ε_A is **not** sign-definite pointwise the way a `κ|∇b|²` would be. `κ ∂ᵢb` comes from the closure's own `diffusive_flux_*` rather than a diffusivity passed in, which is why the buoyancy has to be a tracer the closure diffuses (`BuoyancyTracer` only, enforced with an error).
- **Units convention.** The offline pipeline is written in density: `Υ = g(z − z✶(ρ))/ρ₀`, Eq. (7) of Wenegrat, Chor & Barkan (2026). A Boussinesq `BuoyancyTracer` model has no g or ρ₀, so the online Υ is the buoyancy form `z✶ − z`, related by `Υ_density = −(g/ρ₀) Υ_buoyancy`. Since `b = g(ρ₀−ρ)/ρ₀` makes `∇ρ = −(ρ₀/g)∇b`, both sign flips cancel in the contraction, so **ε_A — and hence ε_Aˢ — is the same number in either form** and `inv08` compares them directly.
- **It tracks the current sort.** The online ε_Aˢ is tied to the simulation's own sort of the current buoyancy: the budgets have a time-varying reference and no frozen variant (the sweep keeps one of its own).
- **Two profiles, one sort.** The full-field half is measured against b✶ and the filtered-state half against ⟨b✶⟩: that is the filtered-reference split, so the two halves carry different profiles on purpose. Both come from the one `VerticalSort` column (⟨b✶⟩ is that column's b✶ filtered on the coarse grid and interpolated back), so every filter scale still shares one sort. Offline, `local_potential_energies_timeseries` does the same: the filtered density's reference height is a nearest-density lookup in ⟨ρ_*⟩, the full field's in ρ_*.
- **The second term differs from the offline one by construction.** Online ε_Aˡ contracts the *filtered flux* `filter(κ∂ᵢb)` with ∇Υ̃; offline term 2 rebuilds the flux from the filtered density as `κ∇ρ̄`. Filtering the flux rather than recomputing it is what makes ε_Aˡ the sink of the filtered-state budget when κ varies in space. For the constant κ used here the two agree in the interior (filtering and differencing are both convolutions on a uniform grid, so they commute) and part ways only against the walls, where the filter's edge extension and the derivative's one-sided stencil disagree.
- `inv08_compare_sfs_ape_dissipation.py` measures what is left of that, plus a conservative-vs-centered discretization gap: the online form pairs its two factors on the face where both differences live and interpolates the *product* to the center, while the offline `calculate_gradient` takes centered derivatives at the center and multiplies *those*. Being a difference of two comparable quantities, ε_Aˢ could have amplified that the way ε_Kˢ does; measured at Nz=192/Re=262, before the filtered reference, it does not, landing at 7.8e-02 (field) and 1.4e-01 (∫ε_Aˢ dV) for ℓ=1, and 4.0e-02 / 1.1e-01 for ℓ=7.
- The offline expression stays in `calculate_sfs_ape_dissipation` (`aux01_pe_functions.py`) as the independent implementation `inv08` and `offline/05` compare against, in the same way the offline Π_K and ε_Kˢ paths live on in `validation/` and `offline/04 --recompute-online-terms`.

#### Fully online SFS budgets
Every term of both sub-filter budgets is written by the simulation; `01_online_budgets.py` assembles the budget files from them, and `inv10_online_budget_closure.py` checks closure from the `_int` series alone (the same metric `test_budgets.py` applies to the assembled files):
- **KE**: `residual_K = −∂ₜKˢ + Π_K − ε_Kˢ + τ(w, b_r)`. **APE**: `residual_A = −∂ₜEₐˢ − τ(w, b_r) + Π_A − ε_Aˢ + Rˢ`. The transport `∂ᵢFᵢˢ` is not computed in either, as offline: it integrates to zero over the closed domain.
- **Tendencies** are written both as full fields (`dKs_dt_ℓ<ℓ>`, `dEas_dt_ℓ<ℓ>`) and as tendencies of the integrals (`..._int`, the budget-closure form). They come from Oceananigans' `TimeDerivative`, listed among the outputs as `TimeDerivative(x)` like any other: each writer registers a callback for every `TimeDerivative` among its outputs, on `PrecedingIterations` of its schedule, so the operand is evaluated on the iteration before the writer actuates and again when it does, and the record holds the backward difference over that single timestep, (aⁿ − aⁿ⁻¹)/Δt labelled tⁿ. `PrecedingIterations` cannot anticipate a `ConsecutiveIterations` schedule on its own and falls back to every iteration, which would filter Kˢ and S̃ on every time step; the simulation script defines `actuates_next_iteration` for `ConsecutiveIterations` to prevent that (it belongs upstream). R's internal ∂ₜb✶ and each scale's ∂ₜ⟨b✶⟩ are read by R rather than written, and reading a `TimeDerivative`, `compute!` included, does not advance it, so each is a `TimeDerivativeCallback` in `simulation.callbacks`, on `PrecedingIterations(output_schedule)`, the 3D writer's schedule, whose actuations include the 2D writer's. Left on the callback's default of every time step, they would re-sort the column every step: at the CI resolution one update took 0.15–0.3 s locally, against 0.12 s for a plain CI step.
- **R is built from the reference profile's own time derivative**, not from `∂ₜeₐ − Υ∂ₜb`. The latter is cheaper but makes `Rˢ` contain `∂ₜEₐˢ` identically, so the APE budget would close in its tendency by construction rather than as a test. `ReferenceTendencyCorrection` differentiates only the reference profile (b✶ for R, ⟨b✶⟩ for R̃ˡ), cumulatively integrates it over the sorted column (whose slots are equal-volume, hence uniformly spaced, so `Ψ̇` is piecewise linear on a uniform grid) and evaluates between `z✶` and `z`.
- **The first output pair is not a budget statement.** Its derivatives span the initialisation transient where `∫Eₐˢ` climbs from zero to its working value. `inv10` drops both records (`--skip`, default 2).
- **The online Eₐˢ is S̃, and is non-negative.** Against the unfiltered b✶ the remainder filter(eₐ) − eₐˡ has no fixed sign under an x–z filter: Jensen needs the filter to act on b alone (`test_jensen.py`). Against ⟨b✶⟩ it is S̃ of the filtered-reference split, non-negative up to the nearest-slot lookup, which `test_jensen.py`'s online test asserts to 3e-3 of rms.
- Measured at Nz=1024 on 2026-09-17 with the filtered-reference set (inv10, posted in PR #68), residual/min(terms) is 0.12% (ℓ=1) and 0.56% (ℓ=7) for KE, and 0.51% and 2.1% for APE. The earlier figures at Nz=192/Re=262 (KE 8.8% and 0.53%, APE 5.5% and 1.9%) were for the unfiltered formulation. Since 2026-09-29 the metric is rms(residual)/mean(rms(terms)), at 1% online (`test_budgets.py`, `inv10`) and 3% for the offline pipeline's own budget (`test_offline_check.py`): normalised by the smallest term, a 1.6% discretisation difference in the offline ε_Aˢ read as 20% of ∫Rˢ dV at ℓ=7 and failed CI at Nz=512. Under it the online budgets close to 0.46%/0.40% (APE, ℓ=1/7) and 0.85%/0.19% (KE) at Nz=512, and 0.14%/0.18% and 0.48%/0.29% at Nz=1024 (`filtered_reference_decisions.md` §10).

## Physics Reference

- **TPE** = integral of g*rho*z dV  (total potential energy)
- **RPE** = minimum PE achievable by adiabatic rearrangement (from sorted reference state)
- **APE** = TPE - RPE  (available for conversion to KE)
- **Π_K**, **Π_A** -- cross-scale energy transfer (sub-filter to resolved)
- Physical constants: `g=9.81`, `rho_0=1025`
