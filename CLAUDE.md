# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

KHAPE (Kelvin-Helmholtz Available Potential Energy) computes Available Potential Energy (APE) from Kelvin-Helmholtz instability simulations using the Winters et al. (1995) sorting method. The pipeline is:
1. **Julia simulation** (Oceananigans.jl on GPU) -> NetCDF output, including every term of the sub-filter KE and APE budgets at the online filter scales
2. **Python post-processing** -> assemble and plot the budgets from those online terms; the offline recomputation of the same terms is kept only as a CI cross-check; the sweep over filter scales stays offline

GitHub remote: `git@github.com:tomchor/CoarseGrainedKHAPE.git`

## Running the Code

### Full pipeline (simulation + post-processing + sweep)
```bash
bash submit_all_pbs.sh                        # default Nz=512, the largest 3D run one A100 holds
bash submit_all_pbs.sh NZ=1024                # 4 GPUs (one Casper A100 node) by default, merged in the same job; see Multi-GPU runs
bash submit_all_pbs.sh NZ=256 FIXED_REF=1    # custom resolution; FIXED_REF applies to the sweep transfer only
bash submit_all_pbs.sh SIMULATION=0 PLOTS=1   # the same chain from budgeting on, on the run already in $KHAPE_OUTPUT_DIR
```
Jobs are chained via PBS `afterok` dependencies. Always use `submit_*.sh` wrappers, never submit `*.pbs` files directly.

### Simulation only
```bash
bash submit_simulation.sh NZ=512
```
The job runs the simulation and then, in the same job, `plot3_b_br_snapshots.py`, `plot5_budgets.py` and `plot6_panels.py`, the three figures that need only the simulation's own files (a failing figure is a logged warning, not a job failure, so `afterok` chains still start); the wrapper passes `$KHAPE_PYTHON` to it for that. On several GPUs it merges the rank files first (see Multi-GPU runs).

### Multi-GPU runs
```bash
bash setup_mpi_env.sh                         # once per machine: MPI.jl to Casper's CUDA-aware OpenMPI, via MPItrampoline
bash submit_simulation.sh NZ=1024             # NGPUS defaults to 4 (one A100-80GB node) for 512 < NZ ≤ 1024
bash submit_simulation.sh NZ=1024 NGPUS=8     # two nodes, if four turn out too tight
```
`NGPUS` (both wrappers; default from `default_ngpus` in `khape_defaults.sh`: 1 up to NZ=512, 4 up to NZ=1024, required beyond) picks the path. One GPU is the job as it always was, no MPI. More is whole 4-GPU A100-80GB nodes (`NGPUS` a multiple of 4), `mpiexec` with one rank per GPU and `--ranks NGPUS`, the domain split into x-slabs; every rank writes its own `<stem>_rank<r>.nc` and `<stem>_2d_rank<r>.nc`, and once the ranks have finished the same job, back in the one-GPU environment (no MPI), stitches them with `merge_rank_output.jl` into the two files a one-GPU run writes (the 3D one virtually, in seconds, over the rank files, which must stay; see *Multi-GPU (distributed) runs*; ~3 min at Nz=1024 with the 2D copy) and draws the figures and the animation the one-GPU job draws (a failed merge fails the job, a failed figure does not); everything downstream waits on the simulation job, as on one GPU, and reads the merged files unchanged. The merge used to be a CPU job of its own, `merge.pbs`, chained with `afterok`; folded in, it costs the four GPUs ~10 min idle and saves a job and its queue wait. The job gets the rank count as `RANKS`, not `NGPUS`, which PBS and NCAR's `set_gpu_rank` use for the per-node count. `SAVE_SORTED` and `VALIDATE` are refused on several GPUs (the two model-grid sorts would each sort one rank's slab). `setup_mpi_env.sh` builds MPIwrapper (at the revision `MPItrampoline_jll` names) against the system OpenMPI (`intel/2025.2.1 openmpi/5.0.8`, built with CUDA and UCX) and makes a Julia environment (`$KHAPE_MPI_ENV`) holding MPIPreferences' choice of `MPItrampoline_jll`, and a depot of its own (`$KHAPE_MPI_DEPOT`, default `$WORK/.julia-mpi`). MPI.jl is not pointed at the system library directly because every MPI-built JLL follows its choice of ABI: with the system OpenMPI chosen, HDF5_jll (under NCDatasets) loads `OpenMPI_jll`, a second OpenMPI (5.0.11 against Casper's 5.0.8), and the two cannot share a process (`undefined symbol: opal_single_threaded`); through MPItrampoline MPI.jl and HDF5_jll share one library, and MPIwrapper forwards every call, GPU pointers untouched. `simulation.pbs` stacks the environment on the load path, puts the depot first on the depot path and exports `MPITRAMPOLINE_LIB` for multi-GPU jobs only, so the tracked `LocalPreferences.toml`, one-GPU jobs and CI keep the bundled MPI (never initialised), and the two builds do not overwrite each other's caches (their cache files are not keyed on the MPI choice). It also sets `JULIA_CUDA_MEMORY_POOL=none` (CUDA IPC of pooled memory, MPI.jl's known issues), takes the cuda module's toolkit (12.9) back off `LD_LIBRARY_PATH` (the dynamic linker searches it before a library's RUNPATH, so CUDA.jl's own 12.6 libraries picked up `libcublasLt`, `libcusparse` and `libnvJitLink` from it, "loaded from a system path"; OpenMPI, UCX and MPIwrapper need only the driver and find the rest through their RPATHs), sets `UCX_ERROR_SIGNALS` and `UCX_MEMTYPE_CACHE` before Julia starts (MPI.jl sets them in its `__init__`, after MPItrampoline has loaded UCX, which has read its settings by then, "unused environment variables", and so kept SIGSEGV, which Julia uses to stop threads for GC: with 8 threads per rank UCX caught an idle thread's GC safepoint within a minute and aborted the run, `Caught signal 11 (Segmentation fault: invalid permissions for mapped object)`; `kelvin_helmholtz_instability.jl` also sets both on its first lines, before anything loads MPI, so any launch gets them), forwards the ranks' environment with `mpiexec -x` (a second node gets PBS's, not the script's), precompiles once before launch, and logs every GPU's memory to `logs/kelvin_helmholtz_<NZ>_gpu_memory.csv`.

Account: `$KHAPE_ACCOUNT` (default `UMCP0061`), which every submit wrapper passes with `qsub -A` (and `$KHAPE_PYTHON`, default `$HOME/miniconda3/envs/py313/bin/python`, for the Python jobs and for the figures the simulation job draws after the run; both defaults live in `khape_defaults.sh`; see README, Environment); queue: `casper`, 1x A100-80GB (`gpu_type=a100_80gb`: plain `a100` can also land on Casper's 40 GB PCIe A100s), 8 cores, 64 GB RAM.

The Julia simulation accepts CLI args: `--Nz`, `--Ri`, `--stop_time`, `--Re0`, `--Pr`, `--U`, `--h`, `--perturbation_amplitude`, `--output_interval` (time between outputs, default 2; CI uses 4), `--filter_ls` (one or more online filter length scales ℓ; default `1 7`; every term of both SFS budgets is written at each), `--save_tensors` (flag; also writes the per-scale strain/stress tensor components for online-vs-offline validation), `--save_sorted` (flag; also writes the validation-only view of the Winters (1995) sorted reference state: the two model-grid z✶ methods, the sorted column, ∫E_b), `--offline_check` (flag; also writes the record one time step after each 3D output, the consecutive-iteration pair the offline pipeline differences for its own tendencies; `pytest --offline-check` needs it, the online tendencies do not, and it doubles the 3D output), and `--ranks` (MPI ranks, one GPU each, default 1; more splits the domain into that many x-slabs, must divide Nx and Ny, and must equal the number of processes `mpiexec` launches, which the script checks). For local CPU development:
```bash
julia --project -t 8 kelvin_helmholtz_instability.jl
julia --project -t 8 kelvin_helmholtz_instability.jl --Nz 128 --Ri 0.1 --stop_time 70 --Re0 0.4 --output_interval 4   # CI's run
julia --project -e 'using MPI; run(`$(MPI.mpiexec()) -n 2 $(Base.julia_cmd()) --project kelvin_helmholtz_instability.jl --Nz 32 --ranks 2`)'   # 2 ranks, CPU
julia --project merge_rank_output.jl output/khi_Nz32_Ri0.10      # then stitch the rank files
```

### 3D isosurface figures
```bash
cd postprocessing
bash submit_render3d.sh TIMES=100,120,140              # X13 at each time; default panels are the six budget terms at ℓ=1
bash submit_render3d.sh FROM=60 TO=160 EVERY=10       # a strided range instead of a list (EVERY has no default)
bash submit_render3d.sh TIMES=120 LEVELS=2             # fewer isosurfaces: much faster under software rendering
bash submit_render3d.sh TIMES=120 FILE=/glade/.../khi_Nz1024_Ri0.10.nc
```
`render3d.pbs` asks for **no GPU**. GLMakie needs an OpenGL context, not a GPU, and a Casper compute node has
neither a display nor the NVIDIA driver exposed to one; `/usr/bin/Xvfb` plus Mesa's software rasteriser
(`LIBGL_ALWAYS_SOFTWARE=1`) gives one on a plain CPU node, so this is an ordinary batch job needing no modules,
no VirtualGL and no FastX session. The job starts its own Xvfb on a free display, smoke-tests the context before
rendering (a long software render should not be how a broken display announces itself) and kills the server from
an EXIT trap. Two traps: `xvfb-run` is **not** installed on Casper, only the `Xvfb` binary it wraps, and
`julia +1.13` is a juliaup feature that Casper's `julia` reads as a filename, so the job finds 1.13 the way
`simulation.pbs` does. `TIMES` and `FIELDS` travel colon-separated because `qsub -v` splits its own list on
commas, which is also why a strided range is `FROM`/`TO`/`EVERY` rather than a `100:10:200` literal. Software rendering costs about 90 s per six-panel figure at Nz=1024 (measured), so the job renders its
times sequentially and a full 101-record set is about 2.5 h, well inside one job; `subset_for_plots.py` is still the quicker loop
for tuning camera, levels and colours, since no `qsub` round trip beats a local render.

### Local post-processing (no PBS)
```bash
cd postprocessing
bash 00_get_budgets.sh output/khi_Nz128_Ri0.10.nc --filter-scales 1 7        # 01_online_budgets.py + 02_plot_budgets.py
N_WORKERS=4 bash offline/run_offline_budgets.sh output/khi_Nz128_Ri0.10.nc --filter-scales 1 7   # the offline pipeline, into output/offline/
```
`--filter-scales` must be among the simulation's `--filter_ls` (default: every scale it wrote). The offline pipeline is not a product: it exists for `pytest --offline-check` (below). `N_WORKERS` (default 1) is its parallelism.

### Running tests
```bash
pytest tests/ -v -s                                  # closure, positivity, synthetic filter and Jensen tests (minutes)
pytest tests/ -v -s --offline-check                  # + the offline pipeline as a cross-check (minutes at CI's Nz=128)
pytest tests/test_gaussian_filter.py -v -s           # single file (filter unit tests, no pipeline output needed)
pytest "tests/test_budgets.py::test_ke_budget_residual" -v -s   # single test
julia --project tests/test_distributed_diagnostics.jl            # the multi-GPU pieces on 2 and 4 CPU ranks (about a minute)
```
`tests/test_distributed_diagnostics.jl` runs itself under the bundled MPI's `mpiexec` with 2 and 4 ranks and checks `distributed_diagnostics.jl` against the one-process computation, bit for bit: the Gaussian filter (3D and 2D) of fields at (C,C,C), (F,C,C), (C,C,F) and of two operations, with x stencils wider than a slab and as wide as the domain; the sorted column (also against Oceanostics' `VerticalSort`); and the reference heights a `ProfileLookup` of it assigns; plus, to roundoff, ε̄ as an area integral. It needs no simulation output and no GPU.
`test_budgets.py` checks SFS KE and APE budget closure (rms(residual)/mean(rms(terms)) < 6%, the value CI's Nz=128 run sets (see *Fully online SFS budgets*); the mean rather than the smallest term, so that no single small term sets the metric) and **requires the assembled budget files** in `postprocessing/output/` for `khi_Nz128_Ri0.10`, the CI run (run `00_get_budgets.sh` first; it is parametrized per filter scale via `conftest.py`). That name is set once, as `STEM` in `tests/conftest.py` (`$KHAPE_TEST_STEM` overrides it), with `SIM_OUTPUT` derived from it. `test_filter.py` / `test_gaussian_filter.py` are self-contained unit tests of the offline `GaussianFilter` and need no pipeline output.

`test_positivity.py` checks the energies whose sign is fixed by construction: the local APE Eₐ (of the full field, of the filtered field, and filtered) and the SFS KE ½τᵢᵢ, each held to `min(field) > -tol x rms(field)`. The tolerance is 1e-3 for the APE, whose nearest-slot z✶ lookup leaves a fraction of the domain a hair below zero, and 1e-8 for the SFS KE, which is non-negative by Jensen and so may only lose roundoff (the online Kˢ measured strictly positive at Nz=1024). It reads the fields from the simulation output, under the budget's names through `online_budgets` (the `online_budget` fixture in `conftest.py`; no file holds a copy of them), plus the online `E_a` directly. It also checks the SFS APE S̃ (`test_sfs_ape_is_positive`). `test_jensen.py` explains why S̃ has a sign: on a synthetic wave-displaced stratification it checks that the remainder Eₐˢ **is** non-negative pointwise when the filter acts in x alone (eₐ(·, z) is convex in b, so Jensen applies when every kernel weight sits at one height) and that it goes negative once the filter also acts in z, which is what `filtered_dimensions` does. Those synthetic tests need no simulation or post-processing output; they are the justification for the filtered-reference construction, so they stay. The file's last test applies the bound to the simulation's own `E_as_ℓ<ℓ>`, which is S̃ and so is asserted non-negative — to 5e-2 of rms, as `test_positivity`, since online S̃ carries the nearest-slot z✶ lookup on both profiles; the dip shrinks with the model resolution (−2.6e-2 on CI's 3D Nz=128 run, −1.7e-2 for the 2D code at the same cell size, −1.14e-3 in 2D at Nz=512, −4.8e-5 at Nz=1024), not with the profile's, and the offline pipeline reproduces it to 2e-7. Note that S̃ dips below zero during the small-amplitude phase (t ≲ 6 at ℓ=1, at the 1e-7 level against a developed rms of 1e-3) in both pipelines identically; the whole-run rms hides it, and `test_offline_check.py` asserts the two pipelines agree on it record by record.

**`--offline-check`** (`tests/conftest.py`, off by default; it needs a simulation run with `--offline_check`, whose consecutive-iteration output pairs the offline pipeline differences for its tendencies, and `offline/01` refuses a run whose `offline_check` attribute is 0) runs `postprocessing/offline/run_offline_budgets.sh` unless its output exists in `postprocessing/output/offline/`, then `tests/test_offline_check.py` compares every field and integral of the offline budgets against the assembled online ones, term by term, at tolerances set from measurement on CI's 3D Nz=128 run of 2026-09-30 (S̃ 8e-6, Rˢ 2e-4, τ 3e-2, ε_Aˢ 0.25, Π_A 4e-2 in rms; the 2D Nz=1024 run of 2026-09-26 gave S̃ 1e-5, Rˢ 2e-4, τ 1e-3, ε_Aˢ 6e-3, Π_A 2e-2), plus the offline budget's own closure (the same metric at 50%, a sanity check only: the offline ε_Kˢ and ε_Aˢ take centred gradients where the online ones pair their factors on faces, which puts the offline residual at 23–33% of the mean term at ℓ=1 on the Nz=128 run, 2.3% at Nz=512 and 1.2% at Nz=1024 in 2D, against 3.4–4.3%, 0.85% and 0.48% online; with the online ε_Aˢ substituted the two residuals agree to 1e-5, so the offline closure can never be held tighter than the online one) and the agreement of the per-record minima of S̃; `tests/test_online_vs_offline.py` (the `inv0*` validation scripts, which recompute their quantity offline) runs under the same gate. The offline pipeline is the independent implementation: scipy filtering on a z-padded domain, a numpy sort, an FFT-filtered reference profile, centred gradients. `offline/04_sfs_ke_budget.py --recompute-online-terms` makes it recompute Π_K and ε_Kˢ too, so no row of the check compares an online field with itself.

### CI
GitHub Actions (`.github/workflows/test.yml`) runs on push to `main` and on PR comments starting with `test` (via `test_trigger.yml`, which marks one commit status, `Budget Closure Tests`, pending and dispatches `test.yml` on the PR branch; each test job posts its own status when it finishes, and the `report` job resolves the combined one and then closes any status still pending on the commit, because a commit status never expires and the trigger runs from `main`, so a context it named before a rename on a branch would otherwise stay pending on the PR for good and hide the result at a glance). The CI pipeline: two Julia simulations in parallel (Nz=128, i.e. 72 × 24 × 128 cells, with `--Re0 0.4` so that Re = 258, the Reynolds number the tolerances were calibrated at, and `--output_interval 4`, since on the CPU each 3D record costs about 80 s and the time steps almost nothing: one as production writes it, one record per output, and one with `--save_sorted --offline_check`, whose consecutive-iteration pairs the offline pipeline differences for its own tendencies), then two jobs in parallel: `test-online` (on the production run: assemble the budgets -> pytest -> animation, minutes) and `test-offline-check` (on the paired run: the offline pipeline -> `pytest --offline-check`, minutes at this resolution). Uses `pip install -r tests/requirements.txt` (not conda). Artifacts uploaded per run: `budget-plots` (`figures/*.png`), `validation-plots` (`figures/validation/*.png`, the online-vs-offline comparison figures), `animation-online` (the mp4s the simulation job itself draws from the online 2D fields, panels animations included), `animation-online-budgets` (`anim1_panels.py`, from the same `_2d.nc` slices), `postprocessing-output` and `postprocessing-output-offline` (the integrated budgets of each pipeline). All are uploaded on `always()`, so they survive a failing test — which is when the comparison plots are most useful.

## Architecture

### Post-processing pipeline (`postprocessing/`)

The budgets are computed by the simulation; the Python side assembles and plots them. `00_get_budgets.sh` runs the two scripts in sequence:

| Script | Purpose |
|--------|---------|
| `01_online_budgets.py` | Through `online_budgets` (`src/aux04_online_budgets.py`), read the `_int` integral of every online SFS KE and APE term, one record per output time (every record but iteration 0's, or the upper record of each pair of a `--offline_check` run), and write `<stem>_sfs_{ke,ape}_budget_integrated.nc` under the variable names the offline pipeline used to write. The 3D fields are not copied (at 3D Nz=512 that copy was 316 GB and 3.5 h): their readers call `online_budgets` on the simulation output |
| `02_plot_budgets.py` | Plot the integrated budgets, one figure per filter scale |

`offline/` holds the offline pipeline, which is **not a product** but the independent implementation the CI check runs (`offline/run_offline_budgets.sh`, output in `output/offline/`; see *Running tests*): `01_filter_fields.py` (Gaussian-filter velocity and buoyancy on a z-padded domain), `02_sort_density.py` (Winters sort of the padded field), `03_energy_transfer.py` (Π_A and the APE↔KE exchange), `04_sfs_ke_budget.py` (SFS KE budget; `--recompute-online-terms` recomputes Π_K and ε_Kˢ too), `05_sfs_ape_budget.py` (SFS APE budget: local APE, S̃, ε_Aˢ, Rˢ, tendency). The variant flags they used to carry (`--fixed-reference`, `--reference true`) are gone with the offline product; the sweep keeps `--fixed-reference`.

`sweep*` scripts are the sweep variant (parameter sweep over filter scales; `submit_sweep.sh EXTENSION=odd` runs it with b oddly reflected past the walls into `_odd` files, and a run over a subset of scales, e.g. the wall-extension test `submit_extension_test.sh` submits, tags its files `_l<scales>` so it never replaces the full sweep; `sweep2` writes only the `∫` integrals, which is all its readers use, unless given `--keep-fields`): `sweep1_filter_fields.py` filters, `sweep2_energy_transfer.py` computes transfer, `sweep3_plot_transfer_spectrum.py` plots spectra. The transfer's memory grows with records × cells (the 3D Nz=512 run took 689 GiB of a 730 GiB node in one job; at Nz=1024 the sorted column of the padded domain alone is 421 M slots, 6.3 GiB per record with its slot heights, and the single job ran out of memory), so `SWEEP_PARTS` (`default_sweep_parts` in `khape_defaults.sh`: 1 up to Nz=512, 6 up to Nz=1024) splits the records into contiguous shares, one job each (`sweep2 --part K/N`, into `_part<K>of<N>` files), all at once after the filter, and a small job after all of them joins the files, checking they hold every record once and in order, and runs `sweep3` (`sweep2 --merge-parts N`; `submit_sweep_transfer` in `khape_defaults.sh` submits both). Every quantity is per record, so the split changes no number, bit for bit; within a job `calculate_energy_transfer(integrals_only=True)` computes each scale's integrals before building the next scale, so the eager Υˡ of every scale (43 GiB each for 51 records at Nz=1024) is never held at once; `tests/test_sweep_reference_grid.py` pins both. `submit_sweep.sh FILTER=0` reruns the transfer on the filtered file already in place, and `PLOTS=1` adds the plots job. The sweep stays offline: at its widest scales the matched filter's stencil exceeds one period in x and CUDA's kernel-parameter space in z, and its odd wall extension has no online counterpart.

`postprocessing/validation/` holds the online-vs-offline comparison scripts, each of which recomputes a quantity offline and compares it against the simulation's online output: `inv01_compare_filters.py` (filtered fields), `inv02_compare_ke_transfer.py` (Π_K), `inv03_compare_tensor.py` (the S̄/τ tensor components), `inv05_compare_dissipation.py` (SFS KE dissipation ε_Kˢ), `inv06_compare_sorted_profiles.py` (the Winters sorted reference state: the sorted profile b✶(z✶) and the reference height z✶, for all three sorting methods), `inv07_compare_local_ape.py` (the local available potential energy Eₐ, field and integral), `inv08_compare_sfs_ape_dissipation.py` (the sub-filter APE dissipation ε_Aˢ at every filter scale, field and integral), and `inv09_compare_ape_transfer.py` (the cross-scale APE flux Π_A). `inv10_online_budget_closure.py` checks that the online budgets close from the `_int` series alone (`--offline-stem` sets the offline pipeline's residual beside it). `inv04_animate_comparison.py` makes the animated online | offline | difference version for a chosen `--field` (Π_K, ε_Ks, or a filtered field). `validation.pbs` runs them all. Each writes exactly **one** figure, to `figures/validation/` (their own subdirectory, so they stay separable from the budget and paper figures in `figures/`); CI uploads that directory as the `validation-plots` artifact. The tensor-component comparison (`inv03`) needs a `--save_tensors` run and the sorted-state comparison (`inv06`) a `--save_sorted` run; every budget term is always written.

Standalone visualization scripts (not part of the numbered pipeline; `plots.pbs` runs every `plot*.py`, in name order, so a figure script must take `--filename`):
- `plot2_transfer_spectrum.py` -- cross-scale transfer spectra (from the sweep output)
- `plot3_b_br_snapshots.py` -- b (top row) and b_r (bottom row) snapshots, one column per time (from the `_2d.nc` file; `simulation.pbs` draws it right after the run)
- `plot5_budgets.py` -- 2x2 panel of SFS KE and APE budget time series (assembled from the simulation output by `online_budgets`; no post-processing needed, and `simulation.pbs` draws it right after the run)
- `plot6_panels.py` -- 4-panel snapshot of local SFS budget fields (likewise straight from the simulation output, and likewise drawn by `simulation.pbs`)
- `anim1_panels.py` -- animated version of plot6 panels (requires ffmpeg); reads everything from the `_2d.nc` file, so it needs no post-processing: every panel (the budget terms through `online_budgets`, and the online `b_r`, on the x–z plane the 2D writer slices) and the time series (the `_int` volume integrals of the same records)
- `X13_3d_volume.jl` -- GLMakie volume render and isosurfaces of one snapshot, the only 3D-rendering script (the run is three-dimensional but every other figure reduces it to an x–z slice at the first y index). One `--field` lays the panels out by `--mode` (volume and isosurface of it), a comma-separated list by field, one panel each; `--scale` appends the `_ℓ<ℓ>` every budget term carries, so the six-term figure is one line. `--overlay b` draws a reference field as contours on the two vertical bounding walls -- lines rather than a second set of isosurfaces, which no colour or opacity makes readable (GLMakie ignores `alpha` on a volume contour). Q, enstrophy and speed are derived here from u, v, w, all written at cell centres: the file's own `ω` is the spanwise component alone. Needs an OpenGL context but **no GPU** -- see `render3d.pbs`
- `subset_for_plots.py` -- not a figure: cuts a run down to a laptop-sized NetCDF (chosen fields, chosen records, z cropped, float32) that `X13` reads unchanged, for tuning a figure locally rather than over `qsub`. It copies the grid reconstruction groups, rewriting the z extent to the crop, and drops `virtual_rank_files`
- `X1_…` – `X11_…` -- the extra figures (X for extra), outside the manuscript set: Π hovmöllers, snapshot panels, a thumbnail, sweep-spectrum diagnostics. They write to `postprocessing/extra_figures/` (`EXTRA_FIGURES` in `aux00_utils.py`), never to `figures/`, which is left to the `plot*` scripts; `plots.pbs` does not run them

Shared utilities:
- `aux00_utils.py` -- data loading (`load_dataset_and_grid`, `pad=False` for the simulation's own grid), filtering (`filter_fields`, `GaussianFilter`, `DaskParallelFilter`; `GaussianFilter.apply` runs its passes back to back on one whole field, a single dask task per field, and `_filter_field` filters each run of repeated planes at the two ends of z once, which gives the plain passes bit for bit and saves work wherever the whole padding is in the arrays), domain padding (`_pad_domain_in_z`; `halo=` keeps only that many padded cells in the arrays and leaves the rest virtual, which is how the sweep loads its fields, `sweep_halo`), spatial derivatives (`calculate_gradient`), tensor condensing (`condense_velocities`)
- `aux01_pe_functions.py` -- density sorting (`sorted_timeseries`, which puts back the padded cells a `halo` dataset leaves out, so the column is always that of the whole padded domain, and, like `local_potential_energies_timeseries`, writes each record into a preallocated output as it is done rather than concatenating them, which held every output twice), potential energy calculations (`local_potential_energies_timeseries`), APE budget terms (SFS flux tensor, cross-scale APE flux, total APE dissipation `calculate_ape_dissipation`, SFS APE dissipation, reference-tendency correction R), the FFT-filtered reference profile (`filtered_reference_profile`)
- `aux02_ke_functions.py` -- SFS stress tensor, strain rate tensor, cross-scale KE flux, SFS KE dissipation, full energy transfer pipeline (`calculate_energy_transfer`, with an `include_pi_k` flag to skip Π_K and an `integrals_only` flag, the sweep's, that computes each scale's integrals before the next scale is built)
- `aux03_plotting.py` -- plotting helpers (`budget_colors`, `run_label`, `plot_sfs_budget`)
- `aux04_online_budgets.py` -- the online SFS budgets assembled from the simulation's per-scale terms (`online_budgets`: the term tables with the budget's signs, the differenced-record selection, the `filter_scale` stacking and the residual, lazily); `01_online_budgets.py` writes its integrals to the integrated budget files; the tests, `plot5`/`plot6` and `X2`/`X4` call it on the simulation file for the 3D terms, and `anim1` on the `_2d.nc` slices (with `records="all"`, since the 2D writer never pairs its records, after dropping its first record, iteration 0)

The budget scripts accept `--filename` and `--filter-scales`; the offline and sweep scripts also `--n-workers`, and the sweep `--fixed-reference`. Output goes to `postprocessing/output/` (`$KHAPE_PP_OUTPUT`), the offline pipeline's to its `offline/` subdirectory.

### Data flow between pipeline steps

**Production.** Every term of both SFS budgets is written by the simulation at each online filter scale (`--filter_ls`, default `(1, 7)`): the fields `K_s_ℓ<ℓ>`, `dKs_dt_ℓ<ℓ>`, `Π_K_ℓ<ℓ>`, `ε_Ks_ℓ<ℓ>`, `wb_rs_ℓ<ℓ>`, `E_as_ℓ<ℓ>`, `dEas_dt_ℓ<ℓ>`, `Π_A_ℓ<ℓ>`, `ε_As_ℓ<ℓ>`, `R_s_ℓ<ℓ>`, the two halves of S̃ (`L_ℓ<ℓ>`, `Ea_flt_ℓ<ℓ>`, 3D writer only), the scale-independent `E_a`, and a `_int` volume integral of each term. `01_online_budgets.py` reads them (`load_dataset_and_grid(pad=False)`, keeping the records whose `TimeDerivative` spans a time step: every record but iteration 0's, or, when the file's `offline_check` attribute says the run wrote them, the upper record of each `ConsecutiveIterations` pair, where that derivative is the same single-step difference the offline pipeline forms) and writes the two integrated budget files, with `ape_reference="filtered"`, `budget_source="online"` and `n_pad_z=0` in their attributes; `02` and `test_budgets.py` read those. The 3D terms are never copied to a budget file: `test_positivity.py`, `test_offline_check.py`, `plot5`/`plot6` and `X2`/`X4` assemble the same budgets lazily from the simulation file through `online_budgets` (`src/aux04_online_budgets.py`, also what `01` writes), so `plot5`/`plot6` need no post-processing, and neither does `anim1`, which draws its panels and its time series from the `_2d.nc` file: it carries every per-scale term on the plotted plane with its `_int` volume integral (identical to the 3D file's j=1 plane and integrals up to Float32; in a `--offline_check` run its records are the lower one of each pair, one time step before the instants the integrated files state the budget at, and the animation's panels and time series are both at those records). `anim1` and `X5` take `b_r` from the `_2d.nc` file. The budget filter scales must be among the simulation's online `filter_ℓs`; `01` raises otherwise, and `--filter-scales` defaults to every scale it wrote.

**The offline check** (`offline/`, `pytest --offline-check`) keeps the old data flow among its own steps, in `output/offline/`: `01` pads the domain to 4σ of the widest scale and records the margin, `02` sorts the padded field, and `03`–`05` read the margin back and refuse a sorted file whose `n_pad_z` or `z_extension` differs from the grid they loaded (`check_same_padded_grid`); `05` reuses its per-scale checkpoints only when stamped with the same run (a hash of the dataset's attributes and time axis); `04 --recompute-online-terms` recomputes Π_K and ε_Kˢ rather than reading them, so the check is independent term by term; `05` reads `04`'s exchange term and `03`'s Π_A. `tests/test_offline_check.py` then compares each field of the offline files against the online term in the simulation output, and each integral against the integrated budget files.

**The sweep** (`sweep1`–`sweep3`) is offline and self-contained: it pads to 4σ of ℓ=20, sorts its own column (`sweep2 --fixed-reference` freezes t=0 by sorting it once and broadcasting), and reads nothing from the budget pipeline. Under the default edge extension that padding is virtual (`sweep_halo`, `_pad_domain_in_z(halo=1)`): the fields keep one padded cell past each wall, which the centred gradients at the wall cells read, and scipy's `nearest` mode repeats the wall value from there on, which is all the padding held, so a field that is constant past the wall filters to the same bits on the cells that are kept. The padded fluid is still part of the reference state: `sorted_timeseries` puts the missing cells back before sorting (`n_pad_z_virtual`, with `z_min`/`z_max`/`Lz` those of the whole padded domain), and its column is the padded field's, slot for slot. `sweep1` writes, and `sweep2` holds, Nz + 2 levels instead of 3.7 Nz, and `sweep2` reads the halo back from `sweep1`'s file (`halo_for_run`) as it does the margin, so a file written with the whole padding is still read on its own grid. The integrals agree with the padded computation to roundoff, not bit for bit (2D Nz=1024, five records at the 30 scales: at most 4e-16 of the largest value, two thirds of the values identical; 3D Nz=256, five records at the 30 scales: at most 4e-16): the padded cells added exact zeros to each sum, in a different order, and the one filtered product that is not constant past the wall, w·b_r, is held at its first padded value beyond the halo, where b✶(z) moves it by 1e-17 of its maximum in 2D at Nz=1024 and by 2e-15 in 3D at Nz=256. That last point rests on the walls being quiescent; a run whose wall planes are not uniform needs a wider halo for that product. `EXTENSION=odd` is another extension of b, which `nearest` cannot stand in for, and keeps the whole padding in the arrays (`halo=None`), as does the offline check, whose E_a fields vary with z in the padding. `sweep1` writes one HDF5 chunk per filtered field, which is how the filter hands them over. With one `apply_ufunc` per pass, dask re-chunked each field between passes and handed netCDF 27 pieces per field at 3D Nz=512, each 32 separate runs on disk, into a contiguous variable that netCDF had first filled with NaN from end to end (2.58 TB); that pattern writes at about 70 MB/s where a whole field writes at 2 GB/s, and it, not the filtering, is what made that job take 8 h on 2 of its 18 cores.

### Filtered-reference scale decomposition

> **Why it is this way:** `filtered_reference_decisions.md` is the decision record for this work — what was
> tried, what was measured, and what was rejected. Read it before changing how ⟨ρ_*⟩ is built, how the
> sub-filter flux and dissipation are computed, or how the integrals treat the z padding. Several of those
> choices look arbitrary and are not, and one of them (the coarse column parameterised by levels-per-σ) was
> a wrong turn that cost real time to diagnose and undo.

The resolved reservoir is measured against the vertically filtered reference profile ⟨ρ_*⟩ (⟨b✶⟩ online), and only against it: the `--reference true` comparison path was dropped with the offline product.

The pipeline filters in x, y **and** z (`FILTER_DIMS` in `aux00_utils.py`). For a kernel with vertical extent the two reservoirs cannot both be measured against the unfiltered ρ_*: a fluid at rest filters to a profile that still carries APE against ρ_*, so the resolved reservoir does not vanish at rest and the remainder Eₐˢ = filter(eₐ) − eₐ(ρ̄) goes negative. That is the whole content of `test_jensen.py`.

Wenegrat, Chor & Barkan resolve it by measuring the resolved reservoir against the rest state *as the filter sees it* — the vertically filtered profile ⟨ρ_*⟩ (their Eq. 2.3): `L̃ = Ẽ_A(ρ̄, z)` against ⟨ρ_*⟩, `S̃ = Ē_A − L̃`, `Υ̃ = z̃_*(ρ̄) − z`, and `b̄_r = b̄ − ⟨b_*⟩(z)` — which against ⟨ρ_*⟩ is exactly filter(b_r), since ρ_*(z) depends on z alone. Both reservoirs are non-negative and both vanish at rest, for any kernel, up to the lookup granularity: during the small-amplitude phase (t ≲ 6 at ℓ=1) S̃ is a ~7% residual of two ~4e-6 quantities and dips to −0.7 of that record's rms (|values| ~2e-7 against a developed rms of 2e-3), identically in both pipelines. Measuring both reservoirs against the unfiltered ρ_* is the `g_z = δ(z)` horizontal-filter limit (their Eq. 2.24–2.26), correct only for a horizontal kernel, and is what both pipelines did before PR #68: the negative SFS APE seen in the animations before then was that remainder.

Online, ⟨b✶⟩ is the sorted column (`sorted_column`, what `VerticalSort` builds) block-averaged onto a coarse column of K=1000 levels per σ, filtered there with the vertical marginal of the same Gaussian (a repo-local kernel with device-array weights: Oceanostics' `NTuple` kernel overflows CUDA's parameter space at that width), and linearly interpolated back onto the N slots for the lookup. Offline (`filtered_reference_profile`, the check) it is an exact FFT convolution of the whole column. Measured at Nz=1024 the two differ by ≤1e-5 on S̃ and 0.007% on ∫Π_A (`filtered_reference_decisions.md` §3, §9), below every tolerance of the offline check, so the coarse column stays; porting the FFT online (a custom `compute!` with CUFFT, as `ReferenceTendencyCorrection`) remains possible and nothing now depends on it.

Three consequences worth knowing:

- **The online APE terms are the filtered-reference ones, and they are the budget.** `Π_A_ℓ<ℓ>` / `ε_As_ℓ<ℓ>` / `E_as_ℓ<ℓ>` / `R_s_ℓ<ℓ>` are built against ⟨b✶⟩; no unfiltered counterpart is written. The offline check recomputes them against the exact FFT ⟨ρ_*⟩ with centred gradients: the online ε_Aˢ is the better discretised of the two (it pairs its factors on the faces where both differences live), and at Nz=1024 the two agree to 0.4–0.6% in rms, 0.5% on the integral over the run.
- **`⟨ρ_*⟩` is scale-dependent**, so it is rebuilt inside each filter-scale loop rather than once per run.
- **Cost is essentially unchanged.** The construction is the same lookup and the same cumulative integral against a different profile; the only new work is one 1D convolution of the profile per timestep. The expensive full-field sort in `offline/02` is untouched and still shared. A *frozen* profile is filtered once and broadcast rather than once per output (callers pass `frozen=`, checked against the first and last rows, rather than the function comparing every row), since `sorted_timeseries(fixed_reference=True)` repeats one row — bit-identical, and 12–45× faster at Nz=128.

- **The offline z padding is sized to the widest filter.** `S̃ = Ē_A − L̃` is an identity only where `filter(z) = z`, which fails within one stencil of an array boundary. `required_pad_margin` asks for 4σ of margin; `offline/01`/`sweep1` pad with it and record it on the filtered-fields file, and `offline/02`–`05`/`sweep2` read it back so every step sees the same padded grid (the sweep keeps all but one cell of it virtual under the edge extension; see *The sweep* above). The simulation has no padding: its filter extends the bounded z axis with the wall value, and the walls sit deep in the saturated tanh where E_A ≈ 0, which is why the online S̃ matches the padded offline one to 1e-5. The old fixed `Nz//2` gives a margin of Lz/2 = 12.5, which is just enough for ℓ = 7 (4σ = 11.89) and fails from ℓ ≈ 7.7 — the next scale in the sweep's `geomspace(0.02, 20, 30)`, whose top end needs 33.97. A run at ℓ ≤ 7 is unchanged, bit-identical. **This fixes only the stencil-truncation half of the large-ℓ problem:** a filter whose σ is a third of the domain also flattens ⟨b_*⟩ until its inverse z̃_* is poorly conditioned, and padding cannot fix that. The profile filter itself is an FFT convolution of the column, O(N log N) in its length, so wider padding costs little there.

`test_filtered_reference.py` pins this down on the synthetic field of `test_jensen.py`: S̃ and L̃ are non-negative, both vanish for a fluid at rest while L measured against the unfiltered ρ_* does not, and the remainder construction still breaks on the same field. (L̃ + S̃ = Ē_A is not tested: S̃ is defined that way.) Measured interior min/rms for S̃ is +8.6e-06, +6.9e-05 and +2.0e-03 at ℓ = 2, 4 and 8 cells, against −0.69, −2.31 and −2.67 for the remainder, which is negative over 15–48% of the domain.

**Edge caveat.** S̃ is computed as Ē_A − L̃, an identity that needs filter(z) = z. `GaussianFilter` extends the bounded z axis with its edge value, so within a stencil of a wall the kernel is one-sided and the identity picks up a spurious τ(z, b). On `test_jensen.py`'s shorter column, whose stratification reaches the walls, every violation lives in that band and nowhere else, which `test_filtered_reference.py::test_edge_cells_are_the_only_place_the_identity_fails` asserts; it also fails if that column stops violating at all, or if `EDGE_BAND_SIGMAS` grows past the kernel's 4σ reach. The production pipeline does not meet this, because `_pad_domain_in_z` pads the domain with edge values at load time, by at least Nz//2 cells each side and at least 4σ of the widest filter, putting the physical domain far from the filter's edge.

**The online APE set.** The simulation writes the filtered-reference set per scale unconditionally — `E_as_ℓ<ℓ>` (S̃) with its two halves `Ea_flt_ℓ<ℓ>` (Ē_A) and `L_ℓ<ℓ>` (L̃, 3D writer only), `Π_A_ℓ<ℓ>`, `ε_As_ℓ<ℓ>`, `R_s_ℓ<ℓ>` and the S̃ tendency `dEas_dt_ℓ<ℓ>` — under the plain names, the unfiltered set having been removed entirely so that nothing downstream can read the superseded formulation by accident. Υ̃ is built inside the terms and not written. (`wb_rs_ℓ<ℓ>`, the APE→KE conversion, is filter(w(b − b✶)) − w̄(b̄ − ⟨b✶⟩): its resolved half is on ⟨b✶⟩ like every other term, matching `04`. Upstream's `SubFilterAvailablePotentialToKineticEnergyConversion` reads one profile for both halves, so neither `method=lookup` nor `method=lookup_flt` gives this split; the simulation adds the filtered conversion against b✶ and subtracts it against ⟨b✶⟩, which moves the pointwise field and leaves every integral as it was, since ∫w̄ f(z) dV = 0. It is a reversible exchange, so **neither half of the filtered/sub-filter separation is sign-definite** and no positivity test applies to it — unlike ε_Kˢ or S̃. It is also load-bearing: `inv10` reads `wb_rs_ℓ<ℓ>_int` in *both* budgets, where at Nz=128/Re=262 it is the largest KE term at ℓ=1, and `plot_kelvin_helmholtz_instability.jl` discovers its panel scales from the `wb_rs_ℓ*` names, so removing it deletes every panels animation. `01_online_budgets.py` reads it into both budget files; the offline check builds its own exchange in `04` and compares.) It needed no Oceanostics change: `ProfileLookup` accepts an external profile as a pair of `Field`s and refreshes it on every `compute!` (`refresh_profile_source!(p::Field, time) = compute_at!(p, time)`), supplying one skips the O(N log N) sort, and the two-argument constructors `AvailablePotentialEnergy(model, z✶)` / `FilteredAvailablePotentialEnergy(model, z✶ˡ)` / `AvailablePotentialEnergyCrossScaleFlux(model, filter, z✶ˡ)` let the two halves carry different profiles, composed in the simulation script exactly as `R_s = Field(gf(R_full)) - R_l` already is. Three things that cost real time to learn and are easy to undo by accident:

- **Composed expressions must be wrapped in a `KernelFunctionOperation`** with a trivial passthrough kernel, as every Oceanostics diagnostic already does (`subfilter_ape_ccc` and friends). A writer specialises on the type of its whole output NamedTuple, and an unwrapped `Field(gf(Field(a))) - b` is a deep `BinaryOperation` nest; several of those sent LLVM's instruction selector quadratic (`DAGCombiner::CombineToPostIndexedLoadStore` → `hasPredecessorHelper`) and stalled compilation of the writer for **>45 min at Nz=32**. `flatten` in the simulation script collapses each term to one flat type. Symptom: the run sits at 100% CPU writing nothing, because Julia buffers stdout and stderr when redirected — an explicit `flush` is the only way to see where it is.
- **Keep the 2D panels writer's tuple small and keep the `flatten` wrappers on it.** It carries the per-scale set so `plot_kelvin_helmholtz_instability.jl` draws the panels animation from the filtered-reference fields, which is the whole point, but it is the largest output tuple and therefore where the LLVM stall above bites first.
- **Measured at Nz=128/Re=262**, the online construction beats the offline one on every count: at rest L̃ is 1.09e-07 (ℓ=1) and 8.04e-08 (ℓ=7) against 1.56e-07 and 1.13e-07 offline, with the true-reference `E_a` at machine zero; S̃ min/rms is −9.4e-03 and −1.2e-06 against −2.7e-02 and −1.6e-06, and at ℓ=7 the interior is strictly positive. The online path has no z padding, so the filter's edge band sits in real fluid — measured, that costs nothing here (edge band machine-clean at ℓ=1, worst violation in the interior), because the domain's z walls sit deep in the saturated tanh where b is uniform and E_A ≈ 0.

**Open question:** which grid ⟨b_*⟩ is built on. Offline it is the sorted column, whose slots are uniform only because the model grid is; Oceanostics' filter is grid-general, so building ⟨b_*⟩ on the column with a single rescaled σ would narrow that. The alternative — filter `ReferenceProfileAtHeight` on the model grid, then interpolate onto the column heights for the lookup — keeps both the grid-generality and the height resolution, and needs testing. Note also that Oceanostics' own docstring (`FilteredAvailablePotentialEnergyEquation.jl`, on `FilteredAvailablePotentialEnergy`) still asserts the filtered buoyancy must be measured against the same profile as the full one, which is the assumption this construction overturns.

### Julia layer
- `kelvin_helmholtz_instability.jl` -- main simulation (Oceananigans.jl `NonhydrostaticModel`, `Centered(order=4)` advection, adaptive timestep via `TimeStepWizard`)
- `utils.jl` -- `closest_factor_number()` (FFT-friendly grid sizes), `show_gpu_status()` (the current device only: it used to `device!` through every visible GPU and leave the caller on the last, which would put every rank of a multi-GPU run on one GPU)
- `distributed_diagnostics.jl` -- the two parts of the diagnostics that need the whole domain, written for both paths: `sorted_column(b)`, the sorted reference column, and a `compute!` method that does the Gaussian filter's x-pass across ranks. See *Multi-GPU (distributed) runs* below
- `merge_rank_output.jl` -- stitches a multi-GPU run's per-rank files into the one-GPU layout (run at the end of a multi-GPU `simulation.pbs`): the 3D file as HDF5 virtual datasets over the rank files, the 2D file copied
- `filtered_reference_profile.jl` -- ⟨b✶⟩: the sorted column block-averaged onto a coarse column of `REFERENCE_FILTER_K` levels per σ, filtered there with the vertical marginal of the Gaussian (device-array weights, since Oceanostics' `NTuple` kernel overflows CUDA's parameter space at that width), and interpolated back onto the column's slots
- `online_diagnostics.jl` -- the only budget term Oceanostics does not provide: `ReferenceTendencyCorrection` (R = ∫_{z✶}^{z} ∂ₜb✶ dz̃). The sub-filter APE→KE conversion τ(w, b_r) used to live here too; it moved upstream in Oceanostics PR #301 as `SubFilterAvailablePotentialToKineticEnergyConversion`, which builds both halves of the split from one kernel and one `b✶(z)` rather than differencing two separately-built diagnostics
- Setup: shear flow u(z)=U·tanh(z/h), stratification b(z)=B₀·tanh(z/h) with B₀=U²·Ri/h; perturbation seeded on w, with per-cell noise that also seeds the spanwise direction. The noise is one global array, `abs.(randn(Xoshiro(546), Nx, Ny, Nz+1))`, indexed by global cell and handed to `set!(w, W)` (which gives each rank its part), so every decomposition starts from the same w; it used to be `abs(randn())` per point inside `set!`, which every rank would have repeated over its own slab, and whose draws followed the CPU threads evaluating the function. Defaults U=1, Ri=0.1, h=1. Re = Re₀ Nz^(4/3) (Kolmogorov resolution at fixed Lz), Re₀ = 0.1 by default, so Re = 410 at Nz=512
- Domain: Lx=λ_max (the most-unstable KH wavelength ≈14.1h), Ly=λ_max/3 ≈ 4.7h, Lz=25h; topology (Periodic, Periodic, Bounded); isotropic cells, so `--Nz` sets the whole grid (288 × 96 × 512 at Nz=512). The run is **3D**: Ly holds two to four wavelengths of the dominant 3D secondary instabilities at Ri ≈ 0.1 (the literature survey behind the choice is in the description of PR #72, which made the run 3D). Nz=512 is the largest run one A100 holds (larger ones run on several GPUs, `--ranks`); the y filter at ℓ=7 reaches across the whole width, so at that scale the filter is close to a y-average
- Output: `output/khi_Nz<Nz>_Ri<Ri>.nc` (3D fields, Float64, one record per output time; `--offline_check` writes consecutive-iteration pairs for the offline pipeline's time derivatives) and `output/khi_Nz<Nz>_Ri<Ri>_2d.nc` (x–z slice, Float32). Both carry the run's parameters and its three control flags as global attributes, the flags as 0/1 Ints (`save_tensors`, `save_sorted`, `offline_check`); the Python side reads them through `output_flag` in `aux00_utils.py` and never infers them from a file's contents, so a file from before they were written needs them added (e.g. `ncatted -a offline_check,global,c,i,1 <file>`). The `_gridN` dimension suffix is still detected per file (`model_grid_suffix`), because it is a property of the writer rather than of the run: the 2D file of a `--save_sorted` run is single-grid

#### Online cross-scale diagnostics
The simulation computes, at each scale in `filter_ℓs` (set by `--filter_ls`, default `(1, 7)`), the sub-filter quantities the offline pipeline would otherwise recompute in Python — so they are produced once, on the GPU, and read back later (see Data flow):
- Filtered fields (Oceanostics `GaussianFilter`), the cross-scale KE flux Πₖ = −τⁱʲ S̄ⁱʲ (`KineticEnergyCrossScaleFlux`), and the SFS KE dissipation ε_Kˢ = filter(ε) − ε̄ (where `ε` is the total viscous dissipation `KineticEnergyEquation.DissipationRate` and `ε̄` is `CoarseGrainedKineticEnergyDissipationRate`, the filtered-flow dissipation). For validation only, the resolved strain rate S̄ⁱʲ (`StrainRateTensor`) and sub-filter stress τⁱʲ = filter(uⁱuʲ) − ūⁱūʲ (`subfilter_stress_tensor`) components are also emitted.
- The Gaussian filter is configured to **match the offline filter exactly**: periodic x and y, edge-extended bounded z, stencil truncated at 4σ (matching scipy `gaussian_filter1d`'s default `truncate=4`; Oceanostics defaults to 2σ) and capped at one period along a periodic direction, which is as far as Oceanostics' wrapping reaches (`validate_periodic_widths`); the offline `GaussianFilter` caps identically, so the two share their weights exactly. All i,j ∈ {1,2,3} are kept.
- `Π_K_ℓ<ℓ>` and `ε_Ks_ℓ<ℓ>` (and their volume integrals) are always written and read by `01_online_budgets.py`, as are `K_s_ℓ<ℓ>` and `dKs_dt_ℓ<ℓ>`; the individual S̄/τ components (`S11/S22/S33/S12/S13/S23_ℓ<ℓ>`, `tau11/…/tau23_ℓ<ℓ>`) are gated behind `--save_tensors` and consumed only by `postprocessing/validation/`. The written filtered fields `u_ℓ<ℓ>`/`v_ℓ<ℓ>`/`w_ℓ<ℓ>`/`b_ℓ<ℓ>` use the same `matched_filter` as every term (they once used Oceanostics' 2σ/`:shrink` defaults).
- The online diagnostics come from the Oceanostics 0.21.2 release, and `TimeDerivative` from the Oceananigans 0.113.3 release; the Manifest is resolved with Julia 1.13 and tracks no branch of either. The filtered-reference APE terms are composed in the simulation script from those diagnostics, a filtered full-field term against b✶ minus a filtered-state term against ⟨b✶⟩, and the repository has its own code where Oceanostics has none: `ReferenceTendencyCorrection` in `online_diagnostics.jl`, the coarse-column construction of ⟨b✶⟩ in `filtered_reference_profile.jl` (`filtered_reference_profile`, built from `coarse_column`, `coarse_filter` and `_interp_from_coarse_ccc`), and `flatten`. Oceanostics provides `GaussianFilter`, `StrainRateTensor`, `subfilter_stress_tensor`, `KineticEnergyCrossScaleFlux`, `SubFilterKineticEnergyDissipationRate`, the whole `BackgroundPotentialEnergyEquation`/`AvailablePotentialEnergyEquation` reference-state machinery, `AvailablePotentialEnergyCrossScaleFlux` (PR #295), `SubFilterAvailablePotentialToKineticEnergyConversion` (PR #301), the `FilteredAvailablePotentialEnergyEquation` family, and `AvailablePotentialEnergyDisplacementPotential`/`AvailablePotentialEnergyDissipationRate` (0.20.0 renamed the first from `BuoyancyDisplacementPotential`). Note 0.19.0 renamed `KineticEnergyBuoyancyProduction` → `PotentialToKineticEnergyConversion`; this repo does not use it.

#### Online sorted reference state
Oceanostics' `AvailablePotentialEnergyEquation` module sorts the buoyancy field adiabatically into its minimum-PE state, giving the Winters et al. (1995) reference height z✶. The simulation always builds the sorted column (`z✶_1dsort`, `b✶_1dsort`, on its own N = Nx·Ny·Nz vertical axis) and every APE term reads it through one `ProfileLookup(b✶, z✶)`, so all scales share one sort per output. The column is `sorted_column(b)` (`distributed_diagnostics.jl`): what Oceanostics' `VerticalSort` builds, bit for bit (`tests/test_distributed_diagnostics.jl`), but on a `(Flat, Flat, Bounded)` grid, where `VerticalSort`'s 1×1 Periodic cross-section with its (1, 1, 3) halo costs 9× the data per Field (about 11 GB of the 41 GB a Nz=512 run holds), and of the whole domain on every rank of a multi-GPU run, where `VerticalSort` errors. `--save_sorted` writes the validation-only view of the same state for `inv06`/`inv07`: the column itself, ∫E_b, and z✶ under the two model-grid methods, which describe the same reference state but differ in where they place cells of *equal* buoyancy:
- `z✶_3dsort` (`ThreeDimensionalSort`) and `z✶_heaviside` (`HeavisideIntegral`) — 3D fields on the model grid. Tied cells take consecutive slots in the first and share their layer's mid-height (Winters eq. 11) in the second; the `ProfileLookup` the budget uses puts a tie run at the mid-height of the band it fills, as `HeavisideIntegral` does.
- All of these go in the **main** output file: one `NetCDFWriter` holds both grids (as the upstream `lock_release.jl` example does). The cost is that a writer holding two grids makes Oceananigans suffix every dimension (`x_caa` → `x_caa_grid1` for the model grid, `_grid2` for the column) and rename the metadata groups (`underlying_grid_reconstruction_kwargs` → `grid_1_...`). The Python side reads the plain names, so `load_dataset_and_grid` strips the model grid's suffix at load time (`model_grid_suffix` / `strip_grid_suffix` / `open_grid_group` in `aux00_utils.py`); the column keeps its own suffix and is read by `inv06`/`inv07`. The 2D slice writer gets the model-grid `outputs` plus the per-scale budget terms and `b_r` (all model-grid), so it stays single-grid; those slices are what let `plot_kelvin_helmholtz_instability.jl` draw the SFS-budget panels animation (`animations/khi_Nz<Nz>_Ri<Ri>_panels_l<ℓ>.mp4`, the online counterpart of `anim1_panels.py`) straight from the `_2d.nc` file.
- Only the column is a reference *profile* as written. For the two model-grid methods `reference_buoyancy` is the model's own `b` (already an output), so their profiles come from ordering the (z✶, b) pairs by z✶ — see `profile_from_model_grid` in `inv06`, and the `lock_release.jl` example upstream.
- **b✶ at a cell's own height is a tie, broken by roundoff.** Oceanostics' `reference_buoyancy_at_height` (behind `b_r`, `ReferenceBuoyancyAnomaly`, and the resolved halves of the exchange `wb_rs_ℓ<ℓ>`) reads the slot a cell's height falls in, and with Nx·Ny even every cell centre lies exactly on the face between two slots, so the roundoff of the GPU `sum` and `cumsum` that place the slots (in `sorted_column`, as in `VerticalSort`) picks one, and it differs between GPU models. Measured on 2026-10-02 at Nz=256, 4 V100s against 1 A100: at the levels where the pick flips, `b_r` moves uniformly in x by the gap between the two slots, up to 6e-5 against a max|b_r| of 1e-2 while the flow is still nearly uniform in y (each slot then holds a run of near-equal values), and `wb_rs_ℓ1` by 4e-2 of its maximum; every integral is unchanged (∫w̄ f(z) dV = 0), and on one GPU model any decomposition reproduces both to roundoff (4 A100s against 1: `b_r` 2e-11). Interpolating b✶ linearly between slot centres, upstream, would remove the tie.
- `b✶` recomputes itself: its operand (`GlobalSortState`) gathers the buoyancy and sorts it on every `compute!`, so handing it to an output writer, a `TimeDerivativeCallback` or a `ProfileLookup` refreshes it, status-gated; `z✶` is fixed. (Oceanostics' `VerticalSort` does the same through `SortedBuoyancyState`; an early revision of the branch returned a bare `Field` that `compute!` ignored, which silently wrote the *previous* output's profile.) `inv06` asserts `b✶` is a permutation of `b`, which guards against a regression.
- The **online local available potential energy** `E_a` (the local field, `AvailablePotentialEnergy(model, z✶_lookup)`) and its integral `∫E_a` are always written. `AvailablePotentialEnergy` computes the Holliday & McIntyre (1981) integral density Eₐ = ∫_{z✶}^{z}[b✶(z̃) − b] dz̃, identical to the offline `ape` field in `local_potential_energies_timeseries` (with b = g(ρ₀−ρ)/ρ₀); `inv07_compare_local_ape.py` checks the two, and `01_online_budgets.py` writes it as `Ea(ρ, z)`.
- The API was renamed upstream: `sorted_reference_height` → `reference_height`, `sorted_buoyancy` → `reference_buoyancy`, `OneDimensionalSort` → `VerticalSort`, `AbstractSortingMethod` → `AbstractReferenceHeightMethod`.
- The offline check sorts the *z-padded* domain (`load_dataset_and_grid` pads it with edge values at load time) while the online sort sees only the true domain, so the two do not sort the same field; `inv06_compare_sorted_profiles.py` quantifies that, running the offline sort both padded and unpadded to separate the padding effect from any genuine online-vs-offline difference.

#### Online sub-filter APE dissipation ε_Aˢ
Per online filter scale, the simulation builds the diffusive sink of the sub-filter APE budget from Oceanostics' `AvailablePotentialEnergyDissipationRate`, measured against b✶ and then filtered, and `FilteredAvailablePotentialEnergyDissipationRate`, measured against ⟨b✶⟩. The single-profile `SubFilterAvailablePotentialEnergyDissipationRate` (Oceanostics PR #293) is not used, since it measures both halves against one profile:
- **ε_Aˢ = filter(ε_A) − ε̃ˡ**, with **ε_A = κ ∂ᵢb ∂ᵢΥ** the total APE dissipation, **Υ = z✶ − z** the buoyancy displacement potential, **ε̃ˡ = −q̄ᵢ ∂ᵢΥ̃** with **q̄ᵢ = filter(qᵢ)** the filtered diffusive flux, **qᵢ = −κ ∂ᵢb** (so ε̃ˡ = +filter(κ ∂ᵢb) ∂ᵢΥ̃), and **Υ̃ = z̃✶(b̄) − z**, the filtered buoyancy's reference height looked up in ⟨b✶⟩. Output as `ε_As_ℓ<ℓ>` and `ε_As_ℓ<ℓ>_int`, matching the `Π_K_ℓ<ℓ>` / `ε_Ks_ℓ<ℓ>` naming; `01_online_budgets.py` writes it as `ε_Aˢ`. The offline check recomputes it with `calculate_sfs_ape_dissipation`, and `inv08` compares the two.
- **Only ε_Aˢ is written.** Υ and the total ε_A are Oceanostics' `BuoyancyDisplacementPotential` and `AvailablePotentialEnergyDissipationRate` (both developed here and merged upstream in PR #276); the script builds ε_A and Υ̃ only to form ε_Aˢ; neither is a budget term, so neither is written.
- **What ε_A is.** It is the sink of the local APE equation (the paper's Eqs. 11 and 14, where it enters as −ε_A). With `∂Eₐ/∂b = z✶ − z = Υ`, the diffusive part of `DEₐ/Dt` is `Υκ∇²b = ∇·(κΥ∇b) − κ∇Υ·∇b`. Written out, `ε_A = κ[(∂z✶/∂b)|∇b|² − ∂b/∂z]`: the Winters diapycnal mixing rate less the diffusion the reference state undergoes on its own. The two cancel exactly for a statically stable, horizontally uniform stratification (z✶ = z), so ε_A is **not** sign-definite pointwise the way a `κ|∇b|²` would be. `κ ∂ᵢb` comes from the closure's own `diffusive_flux_*` rather than a diffusivity passed in, which is why the buoyancy has to be a tracer the closure diffuses (`BuoyancyTracer` only, enforced with an error).
- **Units convention.** The offline pipeline is written in density: `Υ = g(z − z✶(ρ))/ρ₀`, Eq. (7) of Wenegrat, Chor & Barkan (2026). A Boussinesq `BuoyancyTracer` model has no g or ρ₀, so the online Υ is the buoyancy form `z✶ − z`, related by `Υ_density = −(g/ρ₀) Υ_buoyancy`. Since `b = g(ρ₀−ρ)/ρ₀` makes `∇ρ = −(ρ₀/g)∇b`, both sign flips cancel in the contraction, so **ε_A — and hence ε_Aˢ — is the same number in either form** and `inv08` compares them directly.
- **It tracks the current sort.** The online ε_Aˢ is tied to the simulation's own sort of the current buoyancy: the budgets have a time-varying reference and no frozen variant (the sweep keeps one of its own).
- **Two profiles, one sort.** The full-field half is measured against b✶ and the filtered-state half against ⟨b✶⟩: that is the filtered-reference split, so the two halves carry different profiles on purpose. Both come from the one sorted column (⟨b✶⟩ is that column's b✶ filtered on the coarse grid and interpolated back), so every filter scale still shares one sort. Offline, `local_potential_energies_timeseries` does the same: the filtered density's reference height is a nearest-density lookup in ⟨ρ_*⟩, the full field's in ρ_*.
- **The second term differs from the offline one by construction.** Online ε_Aˡ contracts the *filtered flux* `filter(κ∂ᵢb)` with ∇Υ̃; offline term 2 rebuilds the flux from the filtered density as `κ∇ρ̄`. Filtering the flux rather than recomputing it is what makes ε_Aˡ the sink of the filtered-state budget when κ varies in space. For the constant κ used here the two agree in the interior (filtering and differencing are both convolutions on a uniform grid, so they commute) and part ways only against the walls, where the filter's edge extension and the derivative's one-sided stencil disagree.
- `inv08_compare_sfs_ape_dissipation.py` measures what is left of that, plus a conservative-vs-centered discretization gap: the online form pairs its two factors on the face where both differences live and interpolates the *product* to the center, while the offline `calculate_gradient` takes centered derivatives at the center and multiplies *those*. Being a difference of two comparable quantities, ε_Aˢ could have amplified that the way ε_Kˢ does; measured at Nz=192/Re=262, before the filtered reference, it does not, landing at 7.8e-02 (field) and 1.4e-01 (∫ε_Aˢ dV) for ℓ=1, and 4.0e-02 / 1.1e-01 for ℓ=7.
- The offline expression stays in `calculate_sfs_ape_dissipation` (`aux01_pe_functions.py`) as the independent implementation `inv08` and `offline/05` compare against, in the same way the offline Π_K and ε_Kˢ paths live on in `validation/` and `offline/04 --recompute-online-terms`.

#### Fully online SFS budgets
Every term of both sub-filter budgets is written by the simulation; `01_online_budgets.py` writes the integrated budget files from them, and `inv10_online_budget_closure.py` checks closure from the `_int` series alone (the same metric `test_budgets.py` applies to those files):
- **KE**: `residual_K = −∂ₜKˢ + Π_K − ε_Kˢ + τ(w, b_r)`. **APE**: `residual_A = −∂ₜEₐˢ − τ(w, b_r) + Π_A − ε_Aˢ + Rˢ`. The transport `∂ᵢFᵢˢ` is not computed in either, as offline: it integrates to zero over the closed domain.
- **Tendencies** are written both as full fields (`dKs_dt_ℓ<ℓ>`, `dEas_dt_ℓ<ℓ>`) and as tendencies of the integrals (`..._int`, the budget-closure form). They come from Oceananigans' `TimeDerivative`, listed among the outputs as `TimeDerivative(x)` like any other: each writer registers a callback for every `TimeDerivative` among its outputs, on `PrecedingIterations` of its schedule, so the operand is evaluated on the iteration before the writer actuates and again when it does, and the record holds the backward difference over that single timestep, (aⁿ − aⁿ⁻¹)/Δt labelled tⁿ. The 3D writer runs on `TimeInterval(2)`, which `PrecedingIterations` anticipates, so one record per output time carries a complete budget; the consecutive-iteration pairs exist only for the offline pipeline, which differences them itself, and `--offline_check` (off by default, on in CI's offline-check run) puts the writer on `ConsecutiveIterations(TimeInterval(2))` to write them. `PrecedingIterations` cannot anticipate a `ConsecutiveIterations` schedule on its own and falls back to every iteration, which would filter Kˢ and S̃ on every time step; the simulation script defines `actuates_next_iteration` for `ConsecutiveIterations` to prevent that (it belongs upstream). R's internal ∂ₜb✶ and each scale's ∂ₜ⟨b✶⟩ are read by R rather than written, and reading a `TimeDerivative`, `compute!` included, does not advance it, so each is a `TimeDerivativeCallback` in `simulation.callbacks`, on `PrecedingIterations(output_schedule)`, the 3D writer's schedule, whose actuations include the 2D writer's. Left on the callback's default of every time step, they would re-sort the column every step: at the CI resolution one update took 0.15–0.3 s locally, against 0.12 s for a plain CI step.
- **R is built from the reference profile's own time derivative**, not from `∂ₜeₐ − Υ∂ₜb`. The latter is cheaper but makes `Rˢ` contain `∂ₜEₐˢ` identically, so the APE budget would close in its tendency by construction rather than as a test. `ReferenceTendencyCorrection` differentiates only the reference profile (b✶ for R, ⟨b✶⟩ for R̃ˡ), cumulatively integrates it over the sorted column (whose slots are equal-volume, hence uniformly spaced, so `Ψ̇` is piecewise linear on a uniform grid) and evaluates between `z✶` and `z`.
- **The first output is not a budget statement.** A `TimeDerivative` reads zero until its operand has been evaluated twice, so iteration 0's record has none, and in a `--offline_check` run the second record's derivatives span the initialisation transient where `∫Eₐˢ` climbs from zero to its working value. `01_online_budgets.py` drops iteration 0's record (and the lower record of every pair), and `inv10` drops the first pair or the first record (`--skip`).
- **The online Eₐˢ is S̃, and is non-negative.** Against the unfiltered b✶ the remainder filter(eₐ) − eₐˡ has no fixed sign under an x–z filter: Jensen needs the filter to act on b alone (`test_jensen.py`). Against ⟨b✶⟩ it is S̃ of the filtered-reference split, non-negative up to the nearest-slot lookup, which `test_jensen.py`'s online test asserts to 3e-3 of rms.
- Measured at Nz=1024 on 2026-09-17 with the filtered-reference set (inv10, posted in PR #68), residual/min(terms) is 0.12% (ℓ=1) and 0.56% (ℓ=7) for KE, and 0.51% and 2.1% for APE. The earlier figures at Nz=192/Re=262 (KE 8.8% and 0.53%, APE 5.5% and 1.9%) were for the unfiltered formulation. Since 2026-09-29 the metric is rms(residual)/mean(rms(terms)): normalised by the smallest term, a 1.6% discretisation difference in the offline ε_Aˢ read as 20% of ∫Rˢ dV at ℓ=7 and failed CI at Nz=512. Under it the 2D budgets closed to 0.46%/0.40% (APE, ℓ=1/7) and 0.85%/0.19% (KE) at Nz=512, and 0.14%/0.18% and 0.48%/0.29% at Nz=1024 (`filtered_reference_decisions.md` §10). CI's 3D run (Nz=128, Δ = 0.195h, Re = 258) closes to 3.4%/1.6% (KE) and 4.3%/4.0% (APE), which is the resolution and not the third dimension: the 2D code at the same cell size and Re gives 3.4%/1.6% and 4.4%/3.9%. The thresholds are therefore 6% online (`test_budgets.py`, `inv10`) and 50% for the offline pipeline's own budget (`test_offline_check.py`, a sanity check at that resolution); the closure of a 3D production run at Nz=512 is still to be measured (`inv10`).

#### Multi-GPU (distributed) runs
`--ranks R` builds `Distributed(GPU(); partition=Partition(x=R))`: x-slabs, because the FFT pressure solver takes no partition in z, and with y whole the filter's y- and z-passes and the 2D writer's j=1 slice stay local to each rank (R must divide Nx and Ny). Oceananigans carries the model itself (halo exchange, the distributed FFT solver, Δt and every reduction all-reduced, so every `_int` output is global and identical on every rank) and needs a CUDA-aware MPI (see *Multi-GPU runs* under Running the Code). What does not carry over on its own, read in Oceananigans 0.113.3 and Oceanostics 0.21.2:
- **The Gaussian filter.** On a rank the partitioned x is `FullyConnected`, so Oceanostics' staged filter takes `EdgeBoundary` with the slab's extent there and clamps at the slab's edges, silently (the stencils at ℓ=7 span the whole period in x). `distributed_diagnostics.jl` adds a `compute!` method for a `Field` of a 2D/3D Gaussian filter on a `DistributedGrid`: it evaluates the operand on the rank, all-gathers the slabs into one global scratch (shared with the sort), runs the x-pass for its own cells from there, wrapping on the global Nx, then the y- and z-passes with Oceanostics' own kernels. It sums the taps in Oceanostics' order, so a filtered field is the one-process one bit for bit, at any location (the face-located fluxes too, which Oceananigans' `TransposableField` would cut at the top z-face). A filter nested inside another operation runs Oceanostics' fused kernel instead, which this does not reach, so `validate_staged_filters` refuses to start if any output would.
- **The sorted column.** `VerticalSort` builds its column on the model's architecture, which on a `Distributed` grid errors. `sorted_column` gathers b and sorts all of it on every rank, so every rank holds the whole column (~0.9 GB per column Field at Nz=1024, about ten of them with the scales' ⟨b✶⟩ and the tendencies), and `ProfileLookup(b✶, z✶)` then works per cell unchanged (its rank-local horizontal area cancels in the slot faces). The replicated column grows 8× per doubling of Nz and does not shrink with R: this design tops out near Nz=1024.
- **`Average(ε, dims=(1, 2))`** divides the sum over every rank by one rank's cell count, R times too large: ε̄ is `Integral(ε, dims=(1, 2))/(Lx·Ly)` on both paths.
- **Output.** `NetCDFWriter` has no notion of ranks (given one filename every rank writes the same file), and a rank's file records its own slab's grid, which `FieldTimeSeries` cannot read back. Each rank writes `_rank<r>` files; `merge_rank_output.jl` writes the two files a one-GPU run does: every variable without an x dimension copied from rank 0 after checking all ranks agree bit for bit, the x coordinates concatenated, each variable's `indices` attribute rewritten to the whole domain, and the grid groups for the whole domain written with Oceananigans' own `write_grid_reconstruction_data!`, on the CPU (a file that says `GPU()` cannot be read where CUDA is not loaded). The 3D file's fields are **HDF5 virtual datasets**, which netCDF-C cannot write but reads as any variable: NCDatasets defines each time-dependent field with an x dimension and leaves it empty, and the script then replaces each, through `HDF5_jll` (the library netCDF-C is built on), with a virtual dataset of the same name, type, attributes and dimension scales that maps every rank file's slab onto its x-range, naming the rank files by their basenames, which HDF5 resolves in the merged file's own directory (it can move as a whole); a read-back of the middle level of the first and last records against the rank files ends the merge. Measured on 2026-10-03 against the files the copy wrote: the Nz=1024 merge takes seconds, plus the 9 GB 2D copy, where the copy took 7 h; every variable reads back identical through netCDF4/xarray, NCDatasets and `FieldTimeSeries`; whole 0.9 GB records read as fast as the copy's, in two tests on differently loaded file systems; and `01_online_budgets.py`, plot3/5/6 and the animations come out identical. Two consequences. A missing rank file reads as fill values, without an error, so the merged file lists its rank files in `virtual_rank_files` and `load_dataset_and_grid` refuses it when one is missing (`check_rank_files` in `aux00_utils.py`). And NCDatasets (0.14) maps only netCDF-C's storage codes for chunked and contiguous, while netCDF-C reports a virtual dataset as virtual (4) or, built on HDF5 2.x as NCDatasets' is, as unknown storage (3), and NCDatasets reads every variable through its chunking: a Julia reader calls `allow_virtual_storage!()` (`merge_rank_output.jl`) first, which is why the 2D file, which `plot_kelvin_helmholtz_instability.jl` reads, is copied instead. The merge used to copy the 3D file, which took an Nz=1024 run's 3.98 TB 7 h 07 min (~155 MB/s) even once it dropped its pages from the cache as it went: a job's memory limit counts the page cache its own I/O fills, and once that filled the 64 GB of the CPU job the merge then ran in, the copy of the Nz=256 rank files ran 17× slower (5 s → 74–90 s per 3D variable, waiting on reclaim). A standalone 3D file, if one is ever needed, is `nccopy -k nc4` of the virtual one (checked identical at Nz=64), which meets the same page cache in a job.
- **Windowed outputs.** The NetCDFWriter writes every output through a window onto its interior (`with_halos = false`), and Oceananigans' distributed `Field` constructor gives a window the x halo-communication conditions anyway, so the first `compute!` of any computed output tried to exchange halo cells the window does not hold and failed out of bounds. `distributed_diagnostics.jl` adds a more specific constructor for x-windowed Fields on a `DistributedGrid` that keeps their windowed (absent) conditions; a window could never exchange halos, so nothing that worked is lost. JLD2Writer defaults to `with_halos = true`, which is why distributed JLD2 output does not meet this.
- **Logging.** Every rank must evaluate the progress message (it reduces over the domain) and a disabled `@info` never evaluates its message, so `progress` builds it first; ranks other than 0 log at `Warn`.
- `--save_sorted` is refused: its two model-grid sorts would each sort one rank's slab.

**Memory diet**, in both paths, with every number unchanged: the filter is memoized by operand (`matched_filter` returns one Field per operand and scale, where ū and v̄ existed three times per scale, w̄ six and b̄ four); E_a and the total APE dissipation ε_A are one Field for every scale; Υ̃ is built once per scale for Π̃_A and ε̃ˡ (`upsilon=`); Kˢ and S̃ are one Field each for their output, integral and tendency; the tendency outputs are `writer_time_derivative`s, since a writer builds its own derivative buffers from the operand and never writes the two `TimeDerivative(operand)` allocates; the column is Flat. The written filtered fields go to the 3D writer as the memoized Fields (read through a view of the interior, no memory) and to the 2D writer behind `flatten` (so its slice reads the computed field rather than filtering again). Measured on 2026-10-02 (`--stop_time 6`, `nvidia-smi` every 5 s): at Nz=1024 on 4 A100-80GB, 57.1 GiB per GPU when the run starts and 67.3 GiB at the peak, of 79.3, with 125 ms per time step, ~67 s per output and about an hour before the first step (39 min of setup and compilation, 22 min for the first output, compilation included), so a run to t=200 takes ~4–4.5 h of the 8 h the job asks for; at Nz=512 on one GPU with `--save_sorted`, the run starts at 23.3 GiB of memory pool against 39.5 GiB before the diet, and peaks at 42.8 GiB in `nvidia-smi` (pool on) against 54 GB. `NGPUS=8` is the fallback should a longer run need more.

## Physics Reference

- **TPE** = integral of g*rho*z dV  (total potential energy)
- **RPE** = minimum PE achievable by adiabatic rearrangement (from sorted reference state)
- **APE** = TPE - RPE  (available for conversion to KE)
- **Π_K**, **Π_A** -- cross-scale energy transfer (sub-filter to resolved)
- Physical constants: `g=9.81`, `rho_0=1025`
